## What can the mux do today toward hosting Let Em Loose agents (fd-fed blocks, adopted ptys, watch-only attach, env strip, Windows remote attach)?
Asked 2026-11-04 (LEL mux-hosted agents design, decision card cmsg_01WgyiM31RsSnZTgNuPX2VE4MQRCC8E9wvaXezDJg8oqev). **No fd passing**: nothing in `rusty_mux` uses SCM_RIGHTS; every block is a server-spawned program on a server-opened PTY (`server/src/state.rs` `BlockRt{pty, process}`; `server/src/pty/linux.rs` `spawn`), so there is no program-less, fd-fed or adopted-PTY block. **Env**: a block always gets the server's environment plus `RUSTY_MUX_{SESSION,WINDOW,BLOCK,SOCKET}` (`pty/mod.rs` `command`; `state.rs` `block_env`); `Launch` carries only program, args and cwd (`proto/src/message.rs` `Launch`, `Features::LAUNCH` bit 11), so env control is a new field and Features bit. **Close**: SIGHUP to the program's process group, SIGKILL after 1 s (`pty/mod.rs` `GRACE`; `linux.rs` `reap`); dropping a block (server stop) kills its group. **Watch-only**: core `attach` takes no lease (`core/src/mux.rs` `attach`/`acquire_lease`); the TUI asks for the lease on focus (`tui/src/main.rs` ~2966), so a no-lease watch is client-side only, but nothing stops another local client taking a free lease (C33 local rules; C46 ownership not started). **Windows**: the `rusty-mux` client builds on Windows but `--ssh` is Unix only (`tui/src/main.rs` ~851), UDP needs `--ssh`, and rusty_term does not link the mux client (D22). Tag: answered.
Source: code paths above on main 2026-11-04; D22, D27; `docs/projects/mux/CAPABILITIES.md` C33, C46.

## Does arc 2 S2's mux mode already have rules for focus, leases and resize?

## Does F6 Reattach (MoveBlock) need a new Features bit for the GUI, and how does it learn which blocks are detached?
Asked 2026-11-06 (arc 2 S4 planning). **No new bit**: `MoveBlock`, `DetachBlock`, `SwapBlocks`, `ResizeSplit` and `MoveWindow` are gated by `Features::LAYOUT_EDIT` (bit 27), which `attach::CONTROL` already asks for, and `GUI` is `CONTROL` plus more, so the GUI already negotiates it (intersection; an old server grants less and the chip then stays hidden). **Detached**: a block whose `Entry::Block.window` is the window but which is absent from that window's `Entry::Window.layout`; live, a `LayoutChanged` that drops a block not preceded by its `BlockClosed` (the server sends `BlockClosed` before the `LayoutChanged` it causes) means it was detached; `BlockCreated` carries its window. There is no detach event. Tag: answered.
Source: `crates/apps/rusty_mux/crates/proto/src/message.rs:133-139,297-308,481-494`; `crates/apps/rusty_mux/crates/client/src/attach.rs:26-35`; `crates/apps/rusty_mux/crates/gui/src/source.rs:47-54`; `crates/apps/rusty_mux/crates/core/src/event.rs:44-55,148-151`.

## On an orphaned block (C46), what happens to its input lease, and may a non-owner take the lease of an owned block before C77?
Asked 2026-11-06 (C46/C77 build thread). **Orphaned:** nobody may type, so the lease is cleared when the block orphans and `AcquireLease`/`Input` are refused; every grant ends and no new grant is possible. **Owned, before C77:** C46 alone does not gate the lease; C77's `Launch.input` defaults to `open` (today's behaviour), so only an `owner-only` block refuses a lease without a grant. ## Is UDP its own address kind in a C35 saved host?
Asked 2026-11-10 (card #280). **No**: every UDP association starts over the SSH control connection (`OpenDatagram` through the forward; the key travels only inside SSH), so UDP is an upgrade of an `ssh` address. The address carries an optional `udp_host` (the `--udp-host` override), and long-lived clients use UDP as `--ssh` does. ctl calls never use UDP. Tag: answered from sources (recorded as D176).
Source: `docs/projects/mux/UDP-TRANSPORT.md` "Bootstrap" 1-5, decision 3; `crates/apps/rusty_mux/crates/tui/src/main.rs:31-47`.
