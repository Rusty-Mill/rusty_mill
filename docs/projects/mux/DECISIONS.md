| 2026-11-01 | C26 login mode (D9): `rusty-mux-server --login MAP [--runtime DIR] <socket>` is a front door, normally root, whose socket any local user may open (0666). It takes the peer's uid (over `--ssh`, the SSH user), maps it to an account by the map file, and relays the connection to that account's own server, which it starts if none answers: as the account (passwd uid, gid, supplementary groups, `HOME`, `USER`, `LOGNAME`, `SHELL`, a fixed `PATH`, cleared environment), in a session of its own, with `/dev/null` for stdin, stdout and stderr (no descriptor the front door opened reaches the account) and `--forwarded-by <front door uid>`, its socket at `DIR/ACCOUNT/server.sock` in a 0700 directory the account owns. The relay starts with a preface (magic `RMXFWD1\0`, then the principal's id and user) that the account server reads only from the forwarder's uid, so its clients carry who connected. The map is a line file, `PRINCIPAL ACCOUNT` with `uid:N`, `user:NAME` or `*`, and an account name or `=` (the principal's own, refused unless the account of that name has the principal's uid); `uid:` beats `user:` beats `*`; a repeated principal or any bad line refuses the whole file; the shipped file is empty; root only through a rule naming the principal. The map must be a regular file (opened without blocking, so a FIFO is refused) of at most 1 MiB, owned by root or the front door's user, writable by no one else, and is read on a thread of its own; account lookups run on the blocking pool, and a connection is admitted against the map in force when they end. The front door's socket gets 0666 from the umask as it is bound, never a chmod by path, in a directory that passes the runtime directory's checks; a stale socket nothing answers is replaced. Each account server is reaped by a thread made before it starts (no thread, no start), needs a pidfd (Linux 5.3; without one it is killed at once and the start fails), and is killed through that pidfd if it does not listen within 10 s; the front door holds at most 1024 connections, 64 per peer uid (those being admitted or waiting for their server included), closes the rest at once, and pauses 100 ms on accept errors from running out of descriptors or memory instead of ending; the runtime directory must be an absolute path with no symbolic link in it, checked before it is created, the front door user's, writable by no one else, and each directory above it root's or that user's and not writable by others unless sticky. The front door relays only to a socket whose peer is the account. Account servers outlive the front door process; under systemd that needs `KillMode=process`, since stopping a unit kills its cgroup (no unit ships yet). A bad map stops the front door at start; SIGHUP rereads it, keeps the old one if bad, and closes only relays whose principal now maps elsewhere or nowhere. A front door that is not root serves only its own account. No PAM yet, no UDP for account servers, Linux only. C33 needs no change: each account server serves one account | One front door for every user, with the account map as the only authority, mirrors Rex's login server without a new crate, dependency or lockfile change (a line file, not JSON). The preface, outside the mux protocol, needs no feature bit or message number, and an old account server refuses root as before | Claude's defaults under the owner's 2026-11-01 go on "the rest of C26, login mode with the account map", **security-relevant**: to be confirmed on the PR.
