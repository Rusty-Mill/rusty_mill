# Risks

| Id | Risk | Impact | Mitigation | Status |
|---|---|---|---|---|
| R1 | ConPTY OSC/sixel/resize pass-through. Both wrappers call `CreatePseudoConsole` with flags 0, so ConPTY re-renders (`MUX-ADOPT-DECISIONS.md` spike 1) | Program status, links and images may be lost on Windows | Spike 1 (flags 0 vs `PASSTHROUGH_MODE` 0x8); side channel if OSCs are stripped. The Windows server keeps flags 0 | open; owner running `spike1-conpty.ps1`. With flags 0, `server/tests/phase1.rs` and `ctl/tests/ctl.rs` pass on CI's Windows leg (merge queue for #1136, #1142): short echoed markers arrive intact. OSC 7501, links and images on Windows are unverified |
| R2 | `rusty_term` fidelity: 15/18 corpus cases match the libghostty oracle; the other 3 are the deliberate DECCOLM divergence (`FIDELITY.md`). The corpus is 80x24, Linux only, final screens only | Wrong screens in untested apps, resize or ConPTY | Fidelity gate on every engine change; ConPTY corpus via spike 1 | open |
| R3 | Roaming transport unspecified | Phase 3 protocol may need rework | Spike 4 ([SPIKE-4-ROAMING.md](SPIKE-4-ROAMING.md)): the frame protocol already resumes across a reconnect; TCP + `rusty_tls` first, own UDP datagrams later, no QUIC (order owner-approved 2026-10-28). Still needed: client resume tokens (the lease stays with the old client) and a heartbeat; the exit test is not yet met | mitigated |
| R16 | `rusty_tokio`'s `LocalRuntime` does not wake its parked loop for a `spawn_local` task's wake; an otherwise idle loop runs it only at its 50 ms park timeout (spike 4) | On an otherwise idle server, a request or keystroke can wait up to 50 ms, locally and remotely | Fixed in `rusty_tokio`: each schedule on the set also wakes the runtime's loop, through a flag checked under the park lock; `tests/local_runtime.rs` checks 20 cross-thread round trips stay under 250 ms (they took about 1 s) | closed |
| R17 | Login mode's front door runs as root and starts servers as other accounts (C26) | A flaw in the map, the account lookup or the start could let one user into another's account | The map starts empty, admits root only by a rule naming the principal, and is refused unless only root or the front door's user can write it; the front door reads only the peer's kernel credentials; the account server trusts a principal preface only from the front door's uid; the start sets groups, gid then uid between fork and exec, with `/dev/null` stdio; `=` reaches only an account of the principal's uid; the runtime directory and its ancestors must be safe from other users; the front door relays only to a socket the account itself serves. Under systemd, account servers survive a restart only with `KillMode=process`. No PAM yet, so expired or locked accounts are still served; names come from NSS (`getpwnam_r`) on the blocking pool, so a slow directory service delays only new connections; the map is read on its own thread; the front door's socket is 0666 from its creation in a directory other users cannot change. `server/tests/login.rs` (root path ignored unless run as root) | open |
| R4 | `rusty_tokio` gaps. Its README says it exists "to understand how an async runtime works, not to replace tokio"; the `rusty_term` runtime and TUI path are tokio-based | Missing features or maturity block the server or TUI client | Decided `rusty_tokio` (DECISIONS); extend it per gap with tests; build the TUI client on `rusty_term_core` (tokio-free), not on `rusty_term`'s tokio runtime | open |
| R5 | Hidden egress in anything adopted | Sovereignty breach | Outbound-connection audit before adoption; phux already fails (`MUX-ADOPT-DECISIONS.md` §1 item 4) | open |
| R6 | Engine version skew between server and clients | Clients diverge from the server's grid | Feature bits in `proto`; snapshot envelope versioned | open |
| R7 | libghostty fork / Zig build | Only matters if a second engine is ever wanted | Not in the runtime path (DECISIONS) | accepted |
| R8 | Rex memory claims (≈400 KB vs ≈5 MB) unverified | Wrong scale targets | Spike 5 with our own numbers | open |
| R9 | `rusty_term` throughput below the libghostty-parity floors after #930 and #936 (local: ascii ≈ 36 vs 58 MB/s target). #936 attributes the rest to memory layout: 24-byte cells and per-line scrollback allocation | Server CPU under floods | #889 open; compact cell and contiguous scrollback (backlog #5, #6) only if a mux benchmark shows the need | open |
| R10 | Windows peer identity across accounts. `rusty_tokio`'s `peer_cred` is gated to Linux and macOS (`crates/libs/async/rusty_tokio/src/io/unix_socket.rs`), so the Windows server checks peers itself | Unverified: whether a second account is stopped at `connect` by the socket's DACL, or only by the SID check (with its pid-reuse window) | Owner-only DACL on the socket file plus a token-user SID check of the peer pid, failing closed (DECISIONS 2026-10-26; #1109, #1136). Confirming the DACL layer needs a second interactive account (design Q4, CUJ 3) | mechanism in place; DACL layer still unconfirmed, CUJ 3 not run on 2026-10-28 ([WINDOWS-MANUAL-CHECK-2026-10-28.md](WINDOWS-MANUAL-CHECK-2026-10-28.md)) |
| R11 | Detached descendants on Windows: a ConPTY child has no Job Object, so a program started outside the block's console (`start` without `/b`) outlives a closed block | Stray processes after a close | Programs on the console get the close notification (`server/tests/windows.rs`). A kill-on-close Job Object in `WindowsPty` changes every user of it, so it waits for its own PR | accepted; confirmed 2026-10-28: after `close-block`, a `start ping -t localhost` outlived the block, while `start /b ping` died with it in under 1 s ([WINDOWS-MANUAL-CHECK-2026-10-28.md](WINDOWS-MANUAL-CHECK-2026-10-28.md)) |
| R12 | Windows console input code page | Non-ASCII keys could reach a block in the console's code page, not UTF-8 | `read_chunk` reads the console as UTF-16 and returns UTF-8 whatever the code page (#1148, `platform-windows/tests/console_poll.rs`) | closed |
| R13 | Elevated client of an unelevated Windows server | Refused if its token cannot be opened for the SID check | Fails closed | accepted; checked 2026-10-28 on build 10.0.26300: an elevated client of an unelevated server was not refused, `list` worked ([WINDOWS-MANUAL-CHECK-2026-10-28.md](WINDOWS-MANUAL-CHECK-2026-10-28.md)) |
| R14 | Threads per Windows block: the mux adds a reader and a writer thread (64 KiB stacks, `server/src/pty/windows.rs`) and up to 64 KiB of queued output, on top of the exit-watcher thread every `WindowsPty` already starts with a default stack (`platform-windows/src/sys/pty.rs`); each close also runs a short-lived 64 KiB hang-up thread. Total per-block cost is not measured | Memory and threads grow with block count | Accepted for tens of blocks; overlapped pipes on IOCP if a measurement shows the need | accepted, not measured |
| R15 | Invalid UTF-8 from a Windows program | Rust's console stdout rejects it and the attach client stops with "the terminal stopped taking output" | ConPTY emits UTF-8 | accepted, unverified |
