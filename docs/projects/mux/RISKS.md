# Risks

| Id | Risk | Impact | Mitigation | Status |
|---|---|---|---|---|
| R1 | ConPTY OSC/sixel/resize pass-through. Both wrappers call `CreatePseudoConsole` with flags 0, so ConPTY re-renders (`MUX-ADOPT-DECISIONS.md` spike 1) | Program status, links and images may be lost on Windows | Spike 1 (flags 0 vs `PASSTHROUGH_MODE` 0x8); side channel if OSCs are stripped. The Windows server keeps flags 0 | open; owner running `spike1-conpty.ps1`. With flags 0, `server/tests/phase1.rs` and `ctl/tests/ctl.rs` pass on CI's Windows leg (merge queue for #1136, #1142): short echoed markers arrive intact. OSC 7501, links and images on Windows are unverified |
| R2 | `rusty_term` fidelity: 15/18 corpus cases match the libghostty oracle; the other 3 are the deliberate DECCOLM divergence (`FIDELITY.md`). The corpus is 80x24, Linux only, final screens only | Wrong screens in untested apps, resize or ConPTY | Fidelity gate on every engine change; ConPTY corpus via spike 1 | open |
| R3 | Roaming transport unspecified | Phase 3 protocol may need rework | Spike 4 before committing the protocol to a transport | open |
| R4 | `rusty_tokio` gaps. Its README says it exists "to understand how an async runtime works, not to replace tokio"; the `rusty_term` runtime and TUI path are tokio-based | Missing features or maturity block the server or TUI client | Decided `rusty_tokio` (DECISIONS); extend it per gap with tests; build the TUI client on `rusty_term_core` (tokio-free), not on `rusty_term`'s tokio runtime | open |
| R5 | Hidden egress in anything adopted | Sovereignty breach | Outbound-connection audit before adoption; phux already fails (`MUX-ADOPT-DECISIONS.md` §1 item 4) | open |
| R6 | Engine version skew between server and clients | Clients diverge from the server's grid | Feature bits in `proto`; snapshot envelope versioned | open |
| R7 | libghostty fork / Zig build | Only matters if a second engine is ever wanted | Not in the runtime path (DECISIONS) | accepted |
| R8 | Rex memory claims (≈400 KB vs ≈5 MB) unverified | Wrong scale targets | Spike 5 with our own numbers | open |
| R9 | `rusty_term` throughput below the libghostty-parity floors after #930 and #936 (local: ascii ≈ 36 vs 58 MB/s target). #936 attributes the rest to memory layout: 24-byte cells and per-line scrollback allocation | Server CPU under floods | #889 open; compact cell and contiguous scrollback (backlog #5, #6) only if a mux benchmark shows the need | open |
| R10 | No Windows peer identity. `rusty_tokio`'s `peer_cred` is gated to Linux and macOS (`crates/libs/async/rusty_tokio/src/io/unix_socket.rs`) | A Windows server cannot tell which local user connected | Owner-only DACL on the socket file plus a token-user SID check of the peer pid, failing closed (DECISIONS 2026-10-26; #1109, #1136). Whether Windows checks the DACL on `connect` needs a second interactive account (design Q4, CUJ 3) | mechanism in place, manual check pending |
| R11 | Detached descendants on Windows: a ConPTY child has no Job Object, so a program started outside the block's console (`start` without `/b`) outlives a closed block | Stray processes after a close | Programs on the console get the close notification (`server/tests/windows.rs`). A kill-on-close Job Object in `WindowsPty` changes every user of it, so it waits for its own PR | accepted |
| R12 | Windows console input code page | Non-ASCII keys could reach a block in the console's code page, not UTF-8 | `read_chunk` reads the console as UTF-16 and returns UTF-8 whatever the code page (#1148, `platform-windows/tests/console_poll.rs`) | closed |
| R13 | Elevated client of an unelevated Windows server | Refused if its token cannot be opened for the SID check | Fails closed | accepted, unverified |
| R14 | Two threads (64 KiB stacks) and up to 64 KiB of queued output per Windows block | Memory and threads grow with block count | Accepted for tens of blocks; overlapped pipes on IOCP if a measurement shows the need | accepted, not measured |
| R15 | Invalid UTF-8 from a Windows program | Rust's console stdout rejects it and the attach client stops with "the terminal stopped taking output" | ConPTY emits UTF-8 | accepted, unverified |
