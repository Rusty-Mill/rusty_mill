# C79 spike: Windows `--ssh` attach (2026-11-12)

Card #753. This was run on Beast (Windows) through Remote Control, on a release build of `origin/main` at `faf03ad5f`. It was read-only: nothing was written on BaileyAi.

## Answer

No: the Windows clients can't attach to the BaileyAi mux over SSH today. Both ends block it. The Windows client has no `--ssh` route, and BaileyAi has no installed `rusty-mux-ctl` and no running server.

## Setup

- **Build:** `rusty-mux`, `rusty-mux-ctl` and `rusty-mux-gui` all build in release on Windows.
- **OpenSSH:** Windows ships `OpenSSH_for_Windows_9.5p2`, which is above the 8.7 floor in §C79.
- **Host:** the alias `ai` (BaileyAi, Fedora 44) answers `ssh -o BatchMode=yes` with exit 0. Its config also has a `LocalForward` on port 5900 that fails to bind on every connect. That doesn't affect the mux, but it prints a warning each time.

## What breaks

| # | Command | Result | Smallest fix |
|---|---|---|---|
| 1 | `rusty-mux --ssh ai list`, and with an explicit remote socket | exit 1: "--ssh is supported on Unix only for now" (the `cfg(windows)` `remote()` stub in `tui/src/main.rs`) | Take the bridge route in §C79 step 1 ("if it doesn't"). Spawn `ssh HOST rusty-mux-ctl --socket PATH bridge`, run `Conn` over the child's pipes, port `SshPath`/`Route` to respawn the child, and build the argument and hostname parts of `ssh.rs` on Windows. ctl needs no change. |
| 2 | `rusty-mux-gui --ssh ai` | exit 2: "unknown option `--ssh`" | Do (1) first. Then either move the route into `rusty_mux_client` and add `--ssh` to the GUI, or run `rusty-mux --ssh` in a rusty_term tab as §C79 step 3 plans. |
| 3 | `rusty-mux-ctl --host ai list` | exit 2: "--host needs a hosts file: set XDG_CONFIG_HOME or HOME" | On Windows, fall back to `%APPDATA%`. This is minor. |
| 4 | Remote end (read-only checks) | No server is running, nothing exists under `/run/user/1000/rusty_mux`, and `rusty-mux-ctl` isn't on `PATH` | An installed `rusty-mux-ctl` and a running server or front door (§C79 step 4). These are host writes and need Nano's go. |

## Still open

- Whether Win32-OpenSSH streamlocal `-L` works with a Windows AF_UNIX local socket. The spike session's permissions blocked the local forward listener. The bridge route in (1) doesn't depend on it, so this only matters if the forward route is wanted later.
- Attach, detach and reattach across the bridge. This can't be tried until (1) and (4) are done.
