## Verdict
It works. Our own host replaces conhost with no privilege needed and nothing from Microsoft in the process tree. Talking to the console driver is solved. What remains is console behaviour, and most of it maps onto code we already have in rusty_term_core.

## Risks
1. **Ctrl+C.** conhost delivers it through the undocumented user32!ConsoleControl(ConsoleEndTask), which may refuse a caller that isn't conhost. The fallback is uglier. Checking this takes half a day.
2. **Reuse fit.** We haven't checked how well rusty_term_core's Grid fits the Win32 cell model (attributes, ReadConsoleOutput).
3. **Version drift.** Inbox conhost behaviour differs from Microsoft's open-source main (the preamble differs), so pin behaviour with tests, not assumptions.

## Recommended path
1. Half a day: a ConsoleControl probe for Ctrl+C.
2. Two to three days: a thin adapter that feeds WriteConsole/RAW_WRITE into rusty_term_core's parser and Grid, so the reported cursor is real, plus SetConsoleCursorPosition and SetConsoleTextAttribute, then rerun PSReadLine. This proves the reuse number.
3. Then build it for real as a crate in rusty_mill (e.g. `rusty_conhost` under platform-windows), behind a rusty_term option with ConPTY as the fallback, one layer per PR in the order above.

## Update: both risks retired (runs3)
- **Ctrl+C works.** The host calls user32!ConsoleControl(ConsoleEndTask=7, {pid, 0, CTRL_C_EVENT, CONSOLE_CTRL_C_FLAG}) for each attached PID, from an ordinary process with no privilege needed. `ping -t` under cmd stops as it would in a real console, and cmd survives. Calls for processes not attached to us are silently refused. Still open: process groups, Ctrl+Break and CTRL_CLOSE.
- **rusty_term_core reuse fits.** screen.rs (122 lines) sends a single VT stream both to rusty_term_core's parser/Grid (the model) and to stdout (the terminal). GetConsoleScreenBufferInfo now reports the Grid's real cursor. **Interactive pwsh with PSReadLine is usable:** editing, arrows, backspace, tab completion, prediction text, the error prompt, scrolling and wrapping all work.
- Next wall: the output API family (FillConsoleOutput, so Clear-Host fails today; ReadConsoleOutput; WriteConsoleOutput; ScrollConsoleScreenBuffer).
- Model gaps:
  - Win32 stores 4-bit palette attributes, while the Grid stores resolved RGB, so read-back is lossy.
  - The core's pen isn't exported. That needs a small public API addition to rusty_term_core.
  - The buffer is reported as the same size as the window, as ConPTY does.
  - DSR/DA replies must be routed back as input (edit.exe).
- **Revised total:** about 2.2–4.0k more lines and 12–20 days to make cmd, pwsh/PSReadLine and edit.exe usable. The host is 1,318 lines today.
