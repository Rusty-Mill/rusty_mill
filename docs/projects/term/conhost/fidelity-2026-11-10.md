# Windows fidelity corpus on rusty_conhost (2026-11-10)

Card #85, mux risk R1. All 17 sequences in the corpus reach the terminal byte for byte through rusty_conhost, for both writers: 34 of 34 pass. ConPTY, run beside it as a baseline, fails 14 of 34. It drops or rewrites OSC 8 links, BEL, sixel and kitty images.

- **Where:** Beast, Windows 10.0.26300.9818.
- **Commit:** `7bc9a8a48` (branch `claude/conhost-fidelity-corpus`).
- **Test:** `fidelity_corpus_passes_through_our_host` in `crates/libs/ui/rusty_conhost/tests/own_pty.rs`. It fails only on our host's rows; the ConPTY column is information.

To run it again:

```
cargo build -p rusty_conhost --example conhost_probe
cargo test -p rusty_conhost --test own_pty fidelity_corpus -- --nocapture
```

## Method

`conhost_probe` writes each sequence two ways:
- **console:** `WriteConsoleW` with output mode 7 (VT processing on);
- **raw:** `WriteFile` to stdout.

A row passes when the exact bytes appear in what the host sends the terminal and the probe exits 0. The bytes for each sequence are in the test's `CORPUS`.

## What follows

- R1 is closed for the default host: status, links and images reach the mux and the terminal on Windows. No card is needed for our host.
- On the ConPTY rollback (`RUSTY_CONSOLE_HOST=conpty`), links, BEL, sixel and kitty images are still lost. That is a known limit of the rollback, not a target.
- Not covered here: resize, scrollback and rendering. The terminal-side checks are in the switch-over test (card #84).
