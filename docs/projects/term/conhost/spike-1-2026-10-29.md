# Console host spike 1 (#1222, Beast, 2026-10-29)

Source: C:\dev\conhost-recon\spike.md, with raw logs in C:\dev\conhost-recon\runs\. The code lives in C:\dev\conhost-recon\rusty_conhost, outside rusty_mill. It is std-only Rust, and the file carries the MIT notice because its layouts and constants come from microsoft/terminal.

## Built
`rusty_conhost.exe <cmdline>` is about 560 lines. It:
- opens `\Device\ConDrv\Server`, then `\Reference` under it;
- registers the input event with SET_SERVER_INFORMATION;
- spawns the client with PROC_THREAD_ATTRIBUTE_CONSOLE_REFERENCE (0x2000A) and a HANDLE_LIST carrying \Input, \Output and a duplicate of \Output for stderr;
- runs an overlapped READ_IO/COMPLETE_IO loop, so a stdin thread can complete a pending read.

Handled: CONNECT, CREATE_OBJECT, CLOSE_OBJECT, DISCONNECT, RAW_WRITE, WriteConsole, GetConsoleScreenBufferInfo (fixed 120x30), GetConsoleInput (pends), Get/SetConsoleMode and GetConsoleCP. Everything else gets STATUS_NOT_IMPLEMENTED and is logged.

## Results (no conhost or OpenConsole in the process tree)
- probe_client works end to end: text out, the size query, and one key in.
- `cmd /c echo hi` prints `hi` (252 ms). `pwsh -NoLogo -NoProfile -Command "Write-Host hi"` prints `hi` (452 ms).
- Interactive cmd prints its banner and prompt, then calls ReadConsole (0x01000005), which isn't implemented, so it exits.

## Protocol facts
- CONNECT has Process=PID and Object=TID, an input of 1340 bytes and an output of 24 bytes.
- Process-wide calls arrive with Object=0.
- There is no CREATE_OBJECT for the inherited std handles.

Conclusion: talking to the driver is solved. The remaining risk is in reproducing console behaviour.

## Extra protocol facts and model gaps (full spike.md from Beast)
- CONNECT: Process=PID, Object=TID, in=1340 (CONSOLE_SERVER_MSG), out=24 (CD_CONNECTION_INFORMATION). Later Descriptor.Process echoes our process cookie.
- The server handle is opened with NtOpenFile options 0 (async). Every IOCTL is overlapped with its own event.
- The input event is manual-reset. It is set while the queue is non-empty and reset on every drain. Forgetting the reset made edit.exe spin through 598k NOWAIT reads in 15 s.
- pwsh opens CONOUT$ with CREATE_OBJECT type 2. Its CLOSE_OBJECT arrives after DISCONNECT, with Process=0.
- PSReadLine: Console.ReadKey uses peek+NOWAIT (flags 3) and then a blocking read, both with capacity 1. A pwsh2 session made about 1,100 messages, of which 373 were GetConsoleScreenBufferInfo.
- ReadConsole from cmd: unicode, exe "cmd.exe", wakeup_mask 0x200 (TAB), mode 0x1e7, capacity 16384.
- edit.exe: input mode 0x288, output 0xf. It writes ?1049h, ?1002;1006;2004h, ?1036h, OSC 4 0-15, OSC 10/11, ESC[6n and ESC[c, then waits for the replies.
- Ctrl+C:
  - user32!ConsoleControl ordinals: NotifyConsoleApplication=1, ConsoleEndTask=7. CONSOLEENDTASK is {HANDLE pid; HWND; ULONG event; ULONG flags}, 24 bytes.
  - The notify call isn't needed for delivery. The NTSTATUS is always 0, so only the effect tells you it worked.
- Model gaps:
  - Pen lives in the private `cell` module and isn't re-exported.
  - Stored styles (style.rs) DO keep fg_index/bg_index palette tags, so 16-colour read-back can be exact. Only true RGB is lossy.
  - The parser doc comment claiming autowrap is ignored is stale; Grid honours autowrap.
  - rusty_term's encode_frame is pub(crate) in the app crate. The passthrough design makes a re-emitter unnecessary.
