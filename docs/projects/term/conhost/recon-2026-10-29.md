# Console host recon for #1222 (Beast, 2026-10-29)

Source of truth: C:\dev\conhost-recon\recon.md on Beast, with the raw captures beside it. microsoft/terminal is sparse-cloned at C:\dev\conhost-recon\terminal (commit 09beddc6, MIT). These are behavioural notes; no code was copied.

## Key findings
- A normal user process can open `\Device\ConDrv\Server`, which creates a console server. No privilege is needed.
- Simplest path for our host:
  1. Open Server.
  2. Open `\Reference` relative to it.
  3. Spawn the client with PROC_THREAD_ATTRIBUTE_CONSOLE_REFERENCE (attribute 10, undocumented), and pass the \Input and \Output std handles through HANDLE_LIST.
  This needs neither conhost nor conpty.dll (src/server/Entrypoints.cpp StartConsoleForCmdLine; winbasep.h).
- Through kernel32, ConPTY uses inbox system32\conhost.exe: `--headless --width --height --signal 0x.. --server 0x..`. Windows Terminal gets OpenConsole only because it ships its own conpty.dll.
- The inbox conhost on build 26300.9711 sends `?9001h ?1004h` with no DA1. Open-source main sends `ESC[c ?1004h ?9001h`. Treat the preamble as version-dependent.

## ConDrv IO loop (dep/Console/condrv.h, src/host/srvinit.cpp, src/server/*)
- IOCTLs on FILE_DEVICE_CONSOLE:
  - READ_IO = 1. Its input is the previous CD_IO_COMPLETE; its output is a CD_IO_DESCRIPTOR plus the packet.
  - COMPLETE_IO = 2.
  - READ_INPUT = 3 and WRITE_OUTPUT = 4, both taking CD_IO_OPERATION.
  - SET_SERVER_INFORMATION = 7, which registers the input-available event.
- Descriptor: `{LUID Identifier; ULONG_PTR Process; ULONG_PTR Object; ULONG Function, InputSize, OutputSize, Reserved}`.
- Function codes:
  - 1 CONNECT, 2 DISCONNECT
  - 3 CREATE_OBJECT, with types 1 CurIn, 2 CurOut, 3 NewOutput, 4 Generic
  - 4 CLOSE_OBJECT
  - 5 RAW_WRITE, 6 RAW_READ
  - 7 USER_DEFINED, 8 RAW_FLUSH
- USER_DEFINED messages:
  - Header is CONSOLE_MSG_HEADER `{ApiNumber; ApiDescriptorSize}`, then the API struct, then variable data.
  - ApiNumber = (layer << 24) | index (ApiSorter.cpp).
  - Variable input is read at ApiDescriptorSize + 8.
  - Variable output is written at ApiDescriptorSize, with its length in IoStatus.Information.
  - The fixed struct goes back through Complete.Write.
- CONNECT payload and reply:
  - The payload is CONSOLE_SERVER_MSG (conmsgl1.h).
  - The reply is CD_CONNECTION_INFORMATION {Process, Input, Output}, which are opaque cookies that ConDrv echoes back in later descriptors.
- A call that can't finish yet goes on a wait queue and is completed later with COMPLETE_IO.

## Minimum message set
- CONNECT
- WriteConsoleW 0x01000006
- ReadConsoleInputW 0x01000004. With neither NOREMOVE nor NOWAIT set and an empty queue, the reply must pend until input arrives.
- GetConsoleScreenBufferInfo 0x02000007
- CLOSE_OBJECT and DISCONNECT
- Likely also needed:
  - GetConsoleMode 0x01000001 and GetConsoleCP 0x01000000
  - CREATE_OBJECT for CONIN$ and CONOUT$
  - RAW_WRITE and RAW_READ
- The spike logs every ApiNumber it receives and stubs unknown ones with an error.

## ConPTY pipe protocol (winconpty.cpp, PtySignalInputThread.cpp, VtIo.cpp)
- Host stdin carries VT/UTF-8 input; host stdout carries VT/UTF-8 output.
- The signal pipe sends a u16 id followed by a packed body:
  - 8 RESIZE {u16 sx, sy}. A resize that arrives before the client connects is stashed.
  - 2 CLEAR {u16 keepCursorRow}
  - 1 SHOWHIDE
  - 3 REPARENT {u64 hwnd}
- Flushing:
  - There is no timer. A cork counter is held for each console API call.
  - When it reaches zero, the buffered VT goes out as one overlapped WriteFile, with at most one write outstanding.
  - A tainted partial buffer is discarded.
