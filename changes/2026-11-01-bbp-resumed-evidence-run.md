## 2026-11-01 - bbp pairs counts a resumed evidence run as a failed run

- **Fixed:** an evidence run stopped and resumed under its cap was judged by its last `bbp mod` output alone, so a first segment's wall or cap stop, its build and its state timings were lost and a resumed run could load as a clean one (#1326). Each capped `bbp mod` now appends its segment (the build it ran) to `evidence/<task>.segments` under its lock and syncs it to disk before it acts on the task, so a moderator killed mid-run still leaves its segment. `bbp pairs` loads a run with more than one segment as a stopped, failed run under the failed-pair rule: its stop is `resumed: N bbp mod segments` (with `; last: cap` or `; last: wall` when its last output stopped), it has no `spec_wall` and no `replay_equals_live` (so criterion 1 is inconclusive rather than holding on it), and its pair is reported in `failed_pair_costs` with a new `stops` list (each stopped run's arm and reason). A run with no segment record, a cut-off or unreadable one, or a segment built from another commit than its saved output reports is refused. A resume under the same cap is still allowed and still capped.
- **Changed:** the evidence marker is now schema 2 (`"schema":2`). A marker written by an older `bbp` is refused, and an older `bbp` refuses to resume or count a run started under the new one. A failed pair with a stopped run is now listed in `failed_pair_costs` even when its known cost is zero.
- **Known limitations:** a resumed run is counted as failed, not folded: its segments' stops and timings are not combined.
