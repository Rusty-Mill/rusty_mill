## 2026-11-15 - ts-hub: relay, STUN, limits (mesh hub slice H2)

- **Added:** `GET /derp` on the hub's listener. A node proves its node key with a NaCl box and the relay admits only keys in the node table, so it never carries traffic for a stranger. `SendPacket` becomes `RecvPacket`; `PeerGone` when the destination is absent; a full queue drops. `Hub::advertise` puts a one-region `DERPMap` in every netmap. The relay's TLS port for stock clients is slice H5.
- **Added:** `ts_hub::stun::serve`, an RFC 5389 binding responder on a UDP socket.
- **Added:** `Limits` (`Hub::with_limits`): deadlines on the HTTP head, request body, Noise handshake and DERP handshake (10 s); caps on concurrent connections (4096), netmap streams (1024, then `503`) and DERP sessions (2048); a per-sender token bucket on relayed bytes (8 MiB/s, 2 MiB burst; packets over it are dropped, not delayed).
- **Changed:** `NodeStore` gains `has_node_key`.
- **Not in this slice:** TLS for the relay, persistence, ACLs, hostname sanitizing. No new third-party dependency; `crypto_box` is already in the workspace.
- **Tested:** 4 MiB through the relay with matching bytes, a stranger refused, `Derp-Fast-Start`, each deadline closing a stalled peer, each cap, the rate limit (exactly the burst gets through, the session survives), STUN round trip against `ts-stun`.
