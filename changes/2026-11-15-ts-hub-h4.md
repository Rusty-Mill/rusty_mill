## 2026-11-15 - ts-hub: policy from mux principals (mesh hub slice H4)

- **Added:** `Policy`, rules of the form `FROM -> TO` (`Policy::parse`), where each side is `*`, `ts:LOGIN` or `ts-node:NAME`: the same principal ids the mux server's allowlist uses (#1665), so the hub has no ACL language of its own. `Hub::set_policy` swaps the rules and wakes every netmap stream.
- **Added:** the hub starts **closed**. With no rule a node sees no peers and its packet filter is empty. A rule opens every port from source to destination, one way. A node's netmap lists only the peers it has a rule with (either direction), and its packet filter admits only the sources that may reach it (`FilterRule`s with those peers' addresses, or `*` for a wildcard source).
- **Added:** tagged pre-auth keys (`KeyPolicy::tagged: Some(NAME)`). The key, not the node, names the server: the machine that registers with it is `NAME.mesh`, whatever hostname it sends, carries `tag:mesh`, belongs to the `tagged-devices` user, and its principal is `ts-node:NAME.mesh`, as the mux server derives for a real tagged node (`principal_of`). A second machine cannot take the name (`NameTaken`), and a device can never be given a name a tagged key reserves. Other nodes are `ts:LOGIN`, with the login fixed by the operator's key.
- **Added:** keys are checked when created (`InvalidKey`): a login must be writable in a rule (non-empty, no whitespace or `#`), may not be `tagged-devices`, and may not collide with another login's wire user id; a server name must be a lowercase DNS label.
- **Added:** `Hub::remove_preauth` / `NodeStore::remove_preauth`: forget a key so nobody registers with it again. Nodes already registered stay; revoke their machines to remove them.
- **Changed:** the packet filter was allow-all; it is now the policy's. A hub that wants the old behaviour sets `Policy::allow_all()`. `NodeStore` gains `remove_preauth`; `KeyPolicy` and `NodeRec` gain `tagged`. Old tables load (the field defaults to false).
- **Not in this slice:** per-port rules (every granted pair gets all ports), groups, a policy file loader and reload signal (H6, the launcher), and tag names beyond the one `tag:mesh`. The DERP relay still admits any registered node key; a node it may not reach has no key for the peer, so no tunnel forms.
- **Tested:** no policy shows no peers and an empty filter; a rule shows only the peers it names and the filter (checked with `ts-filter`) lets the source in and nobody else; one-way rules; a wildcard source; omit-peers still computes the filter; principals match the mux rule; `set_policy` wakes streams; removed key registers no one and keeps its nodes; parse errors name their line.
