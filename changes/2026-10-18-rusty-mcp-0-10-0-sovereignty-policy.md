## 2026-10-18 - rusty-mcp 0.10.0, and its external dependencies pinned (sovereignty item 10, PR 3 of 3)

- **Why:** items 1 to 9 took `rusty-mcp`'s external dependencies down to seven. Nothing stopped a later PR putting one back, and the breaking changes of item 9 were not yet in the version.
- **Version:** `rusty-mcp` 0.9.0 to 0.10.0. The breaking changes since 0.9.0 are item 9's, described in the 2026-10-15 and 2026-10-17 fragments: metrics and spans are exported as OTLP/JSON over HTTP, `OtelConfig::endpoint` is an OTLP/HTTP base URL (port 4318), `pipeline` returns a `SpanLayer`, `OtelGuard::provider()`, `TraceContext::attach_parent`, `TraceContext::otel_context` and `OtelError::Exporter` are removed, and `OtelError` is now `Endpoint(Signal)` / `Thread(Signal, io::Error)`. The cores (item 5) and the `serve` adapters (item 7) kept the public API or only added to it.
- **Policy check:** `.github/scripts/check_workspace_deps.py` did not classify tiers (it only failed on git copies of workspace members, and ADR-0002 leaves a tier ledger as follow-up work), so there was no Tier S check to extend. It now also pins the direct external dependencies (normal and build, any feature; dev-dependencies are exempt, as ADR-0002 says) of the crates in `PINNED_EXTERNAL_DEPENDENCIES`, which holds `rusty-mcp`: `axum`, `http`, `tower-layer`, `tower-service`, `tokio`, `tracing`, `tracing-subscriber`, each with its reason. A dependency off the list fails the `dependency policy` job, and so does an entry the crate no longer uses, so the list only shrinks: sovereignty item 6 deletes `axum` and the tower pair, item 12 the two `tracing` lines. No workflow change: the job already ran the script.
- **Docs:** ADR-0002 Amendment 1 gets a 2026-10-18 status line; `MCP-NATIVE-PLAN.md` A6 and `RUSTY-MCP-SOVEREIGNTY.md` (items 9 and 10, the OpenTelemetry row) record what is done and what is open (items 6 and 12).
- **Not changed:** any code in `rusty-mcp`; the other MCP crates (`rusty-mcp-client`, `rusty-mcp-demo` and the consumers), which this list does not cover.
- **Verified:** 11 unit tests for the check (a new, build, git or optional dependency off the list is flagged by name; dev and workspace path dependencies are not external; a stale entry is flagged; unpinned crates and same-named packages outside the workspace are ignored; every entry has a reason), the existing 6; the script run on real `cargo metadata --all-features` output passes, and fails when `opentelemetry` is added to `rusty-mcp`'s dependencies or `axum` is dropped without deleting its entry.
- **Known limitations:** the list covers direct dependencies of one crate, not its transitive graph, which is what ADR-0002 means by a tier being a claim about a manifest. It is a pin, not the tier ledger the ADR defers.
