## 2026-10-19 - Mill Board: run as a service

- **Added:** `deploy/` (a systemd unit, `board.env.example`, a README with install, restart, backup, restore and rollback), modelled on how `rusty_remind_me` is supervised. `GET /health` (200, or 503 once the store refuses writes until reopened). SIGTERM and SIGINT stop accepting, then spend at most 10 s waiting for the requests being answered (until their last byte is written), the MCP tool calls running and a backup under way, and exit 0; admission is closed before either wait, so new requests get 503, tool calls are refused and no backup begins, and the transport serves no further request on a connection that was already open. `--backup-dir`, `--backup-secs` (default 86400), `--backup-keep` (default 14): `board-<ms>/store/` is a copy of the store taken under its commit lock and `board-<ms>/settings/` the settings files under fixed names, copied together under the settings lock, which is held across the copy of the store as well, then opened and checked (every card in a project of the copied registry) before it is published; the backup is synced, renamed into place, the backup root synced, and only then are older backups pruned and the store compacted. None of that runs while the store needs a restart after an append of unknown outcome. `--allowed-host` reads `MILL_BOARD_ALLOWED_HOSTS`. ADR-0005.
- **Changed:** a store is held by one process: `MmdbStore::open` takes `<path>.lock` and refuses with "in use by another process", so a stray second instance can no longer diverge from the running one. `Store` gains `health`, `backup` (which returns the main file's name, so the backup is verified against the right file whatever the store is called, `board.records` included) and `compact`, with defaults, so other adapters are unaffected; `MmdbStore::backup` and `compact` refuse while unsettled. A first admin's token is written to `first-admin.token` (mode 600) beside `identities.json` when stderr is not a terminal; on a terminal it is printed once as before.
- **Changed (`rusty_serve`):** a request is counted from its head being read to its response being written in full, and `ShutdownHandle::wait_idle(within)` waits for none to be left. Once `shutdown()` has been called a request arriving on an already open connection is dropped unanswered and an answer still being written says `Connection: close`; nothing else about the server changes.
- **Tests:** `tests/service.rs` - one owner until dropped; a backup that opens as the same board and is pruned; settings that share a file name with each other and with the store all kept; a settings change that arrives mid-copy waits for it, shown by the change having reached the lock rather than by a sleep (removing the lock fails the test); a project emptied and removed between the copy of the store and the copy of the settings cannot leave a card without its project (the old order fails the test); a copy whose cards do not fit its settings is refused (removing the check fails the test); real basename collisions, `config.json` twice and a settings file named like the store; a backup that died part way swept; compaction that keeps the board; a memory board refusing to back up without leaving a partial one; no backup, rotation or compaction after an append of unknown outcome, and the reopen recovers the durable event (removing the compaction guard fails the test); the real binary answering `/health`, refusing a second process on its store, keeping the credential out of stderr and exiting 0 on SIGTERM. `tests/shutdown.rs` - a real MCP `card_add` held in the store past the point where the server switches to an event stream, a stop, and the mutation completed and the reply sent in full before the stop returns; a stuck one ended at the deadline; a second mutation on a keep-alive connection opened before the stop is not run; admission is closed before the listener stops and before the drain waits (the old accounting fails them); stores named `board.records` and `board.inserts` back up and restore. `rusty_serve` - `wait_idle` waits for a response in progress and gives up at its deadline, and ignores an idle keep-alive connection. `tests/web.rs` - `/health`, and requests refused with 503 once a stop has begun while a held one is waited for to a deadline. `src/drain.rs` unit tests - the wait, the deadline, the refusal.
- **Known limitations:** no TLS (plain HTTP, so beyond loopback a proxy is needed). A store that needs reopening is reported by `/health` but not restarted by the process. Backups live on the store's disk until copied off the host. SIGTERM is handled on Unix only. Idle keep-alive connections and long streams are not waited for at a stop; the 10 s deadline and the exit end them.
