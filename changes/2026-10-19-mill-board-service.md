## 2026-10-19 - Mill Board: run as a service

- **Added:** `deploy/` (a systemd unit, `board.env.example`, a README with install, restart, backup, restore and rollback), modelled on how `rusty_remind_me` is supervised. `GET /health` (200, or 503 once the store refuses writes until reopened). SIGTERM and SIGINT stop accepting, wait up to 10 s for the requests running and a backup under way (new ones get 503), and exit 0. `--backup-dir`, `--backup-secs` (default 86400), `--backup-keep` (default 14): `board-<ms>/store/` is a copy of the store taken under its commit lock and `board-<ms>/settings/` the settings files under fixed names, copied as a set under the settings lock and checked to load together; the backup is synced, renamed into place, the backup root synced, and only then are older backups pruned and the store compacted. None of that runs while the store needs a restart after an append of unknown outcome. `--allowed-host` reads `MILL_BOARD_ALLOWED_HOSTS`. ADR-0005.
- **Changed:** a store is held by one process: `MmdbStore::open` takes `<path>.lock` and refuses with "in use by another process", so a stray second instance can no longer diverge from the running one. `Store` gains `health`, `backup` and `compact`, with defaults, so other adapters are unaffected; `MmdbStore::backup` and `compact` refuse while unsettled. A first admin's token is written to `first-admin.token` (mode 600) beside `identities.json` when stderr is not a terminal; on a terminal it is printed once as before.
- **Tests:** `tests/service.rs` - one owner until dropped; a backup that opens as the same board and is pruned; settings that share a file name with each other and with the store all kept; a settings change that arrives mid-copy waits for it (removing the lock fails the test); a backup that died part way swept; compaction that keeps the board; a memory board refusing to back up without leaving a partial one; no backup, rotation or compaction after an append of unknown outcome, and the reopen recovers the durable event (removing the compaction guard fails the test); the real binary answering `/health`, refusing a second process on its store, keeping the credential out of stderr and exiting 0 on SIGTERM. `tests/web.rs` - `/health`, and requests refused with 503 once a stop has begun while a held one is waited for to a deadline. `src/drain.rs` unit tests - the wait, the deadline, the refusal.
- **Known limitations:** no TLS (plain HTTP, so beyond loopback a proxy is needed). A store that needs reopening is reported by `/health` but not restarted by the process. Backups live on the store's disk until copied off the host. SIGTERM is handled on Unix only. Idle keep-alive connections and long streams are not waited for at a stop; the 10 s deadline and the exit end them.
