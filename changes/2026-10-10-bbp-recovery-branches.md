## 2026-10-10 - rusty_bbp_host: the recovery branches a terminal rerun can take

- **Changed (runbook):** step 3 of "Recovering from an environment fault" reads the fresh report before settling: `passed` or a `failed` that executed the tests settles the request; a `failed` with the same environment error means fix and rerun again, nothing granted meanwhile; an `error` has escalated the task with the request still pending, so the human fixes the environment and `resume test --rev N` starts a fresh run before settling; `decision MSG reject` says the fault is not environmental and regrants the Tester to judge the run as it stands. An `answer` settles only the request it replies to and a `decision` only the request it names.
- **Changed (prompts):** the Coder treats a fault as resolved only by an answer replying to its request or a decision accepting it that says the environment is fixed, and then reapplies its previous candidate's diff in its fresh clone (`get_artifact`, `git apply`, `cargo test`) before resubmitting, since the clone no longer holds the change; an empty diff is never a candidate. The Tester judges the card's current selected run only and asks again, with the new log, if a fresh run shows the same kind of failure.
- **Added (tests, `runner_e2e`):** the Coder recovery path (candidate sent back by `revise`, request from `build`, answer, the regranted Coder reapplies the stored diff in a fresh clone and resubmits a nonempty, new candidate); an answer replying to another message is refused and a decision naming another request is posted without settling the pending one or granting a turn; a failed rerun keeping the request open with nobody granted until a later run passes; a rerun that times out in the sandbox (`error`) escalating with the request pending, then `resume test` starting a fresh run and settlement regranting the Tester; a rejecting decision regranting the Tester, who opens a new request. `reach_test_with` is factored into `reach_build_with` and `submit_candidate`.
- **Known limitation:** prompts are text; the next live run shows whether the roles follow them.
