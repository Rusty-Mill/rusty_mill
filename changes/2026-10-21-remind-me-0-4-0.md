## 2026-10-21 - rusty_remind_me 0.4.0

- **Changed:** the six `rusty_remind_me` crates and the plugin move from 0.3.0 to 0.4.0. The minor bump is for the `remind_me_remote` public API change below.
- **Changed:** `remind_me_remote` serves MCP through `rusty_mcp_server` and `rusty_mcp_axum`, not `rmcp`. `build_router` returns `Result<Router, BuildError>`, and `RemindMeHandler` and `InProcessEventStore` are gone from the public API. A standalone `GET` stream is answered with `405`, and `listChanged` is no longer advertised. Resumption with `Last-Event-Id` still works.
- **Changed:** the Bearer scheme is matched case-insensitively and an empty token is rejected up front (shared `rusty_oauth` parser).
- **Fixed:** `daemon stop` reports `stopped` only after connection draining and background cleanup have released the store, and a completed connection no longer has its lifetime extended.
- **Changed:** the legacy AWS rustls client is dropped, and 118 unused dependencies are removed.
- **Tested:** 2,275 tests across the six crates pass on Linux. The built binary was run against copies of a current store (16,230 memories) and a store at schema v31, and against a fresh store. The remote connector was driven by hand over HTTP and connected from claude.ai both with a token URL and through the OAuth sign-in, with all 75 tools listed and a write, read, update and delete round trip.
- **Known limitations:** a connection dropped mid-reply, daemon mode with sync, and the Windows and macOS builds were not exercised. The store must already be at schema v30 or later; a store at v29 or earlier has to be opened once with 0.2.x first. Stop the daemon and back up the whole `~/.remind-me/` folder, including `memory.engine/`, before upgrading.
