## 2026-10-14 - rb_rl_game_bridge: a killed game is "closed", not an error; the game speaks early

- **Fixed:** when Rocket League is killed (the live-test runner does this at teardown) Windows resets the connection instead of closing it, and `rb_rl_bridge` ended with `An existing connection was forcibly closed by the remote host. (os error 10054)` and a non-zero exit, and the bots were dropped with the same error, in all three live runs of 2026-10-13. `RocketLeagueLink` now treats `ConnectionReset`, `ConnectionAborted`, `BrokenPipe` and `NotConnected` on the game's socket as the game going away: a read reports `PollClump::Closed`, which the core ends as `RunEnd::GameClosed`; a write to a reset socket is not a fault (the outbox is dropped) and later commands are refused like an over-budget one, so they are dropped or retried until the next poll ends the run. Any other socket error is still a fault, and a clean close part-way through a message is still `UnexpectedEof`.
- **Verified:** unit tests with a scripted stream (each error kind on read; a reset behind half a frame; a reset write; other errors and a truncated clean close still faults), and `real_core.rs`: a stand-in game that dies with the bridge's `SpawnBot` unread, which makes the OS send a real reset. On Linux the old code ended that run with `Err("Connection reset by peer (os error 104)")`, the same fault as 10054; it now ends `GameClosed`. Each fix was checked to fail without it.
- **Changed (docs):** the 2026-10-13 notes said the game is silent until a map loads. A live run showed `the game connected` (its first message decoding) about 45 s after launch, at the splash screen and before any map, and the committed live fixture opens with two empty menu messages before the map announcement. The README, the doc comments in `link.rs` and `rb_rl_bridge.rs` and the earlier fragment now say the first message can come a while after the game dials. Behaviour is unchanged: silent connections still wait.
- **Known limitations:** the Windows `10054` itself was not reproduced here (a Linux reset is the analogue); not re-run against the real game. The "about 45 s" is inferred from the bridge log file's last-write time, which has no per-line timestamps.
