## 2026-10-27 - OAuth sign-in for Mill Board's MCP server

- **Why:** a claude.ai custom connector signs in with OAuth; the board only took a pasted bearer token. Last of three PRs after `rusty_oauth_server` (#1179) and rusty_tick (#1184).
- **Added (`rusty_mill_board`):** `--issuer` turns on `rusty_oauth_server`'s endpoints, with grants in `--oauth-state` (default `oauth.json` in `--settings-dir`, else `<identities stem>.oauth.json` beside `--identities`, so boards sharing a directory do not share grants). The state file is bound to its issuer on first start, and a board with another issuer refuses to start on it. An actor named by two credentials can neither approve nor use a grant. An IPv6 issuer's host is accepted in both its bracketed and bare forms. The consent page takes one of the board's own tokens. Under `--identities` a grant's subject is the actor and each request resolves it to the actor's current credential, so a role or project change applies at once and removing the agent suspends the grant. Under `--auth-token` a grant is the shared token's caller. An open board refuses an issuer. The issuer's host is accepted as a `Host`. With OAuth on, a `/mcp` 401 carries RFC 9728's `resource_metadata` challenge.
- **Added (`rusty_oauth_server`):** a `serve` feature with the `rusty_serve` adapter (`serve::handle`, `serve::unauthorized`) that rusty_tick carried privately; tick now uses it. `Issuer::host`; `StateStore::bind_issuer`, which ties a state file to one issuer (remind-me and tick do not call it, so their files are unchanged).
- **Known limitations:** rotating an agent's token does not end their grants; re-adding a removed agent of the same name restores them. Delete `oauth.json` with the board stopped to end every grant. Interop with a live claude.ai connector is still not testable from CI.
