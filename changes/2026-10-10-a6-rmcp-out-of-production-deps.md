## 2026-10-10 - MCP plan A6: `rmcp` out of the production dependency graph

- **Removed:** `rusty-mcp`'s `rmcp`-based server scaffold: `run`, `serve`, `ServerConfig`/`HttpConfig`/`Transport`, the CLI, resources, tasks, subscriptions, completion, pagination, `mrtr`, routers, telemetry, shutdown, and the `template/` project. Every consumer had moved to `rusty_mcp_server` (#577); the code is in git history. The `rmcp`, `clap`, `rusty_percent`, `tokio-util` and `schemars` dependencies of the crate went with it, and its `tokio` features were cut to `rt` and `time`.
- **Kept:** `auth` (OAuth 2.1 resource server, JWT with the `jwt` feature), `limits`, `otel` (feature `otel`) and `trace`, which `agentgateway`, `agentgateway-auth` and `agentgateway-mcp` use. Version 0.6.0 (breaking).
- **Changed:** `trace::TraceContext::from_meta` and `apply_to` take the `_meta` object (`serde_json::Map`) instead of an `rmcp` request type; `from_request` is gone. The README is rewritten to match.
- **Tests:** the integration tests that mounted the layers through the old scaffold (`authorization`, `limits`, `otel_metrics`, `trace_context`) now run against a real `rusty_mcp_server` behind `rusty_mcp_axum`, the way the gateway mounts it, via a shared `tests/support`. Same assertions; `tools_can_read_the_verified_token` now also checks the principal reaches a handler through `router_with_principal`. Three scaffold-only tests were deleted with the code (`http_transport`, `completion_and_pagination`, `shutdown`). The long-lived `subscriptions/listen` survives a short timeout, now checked against the real server.
- **Checked:** `cargo tree -e normal,build --workspace --all-features -i rmcp` prints nothing; `rmcp` appears only under `[dev-dependencies]` (wire-format oracles). `rusty-mcp` 74 unit tests, its integration tests and doctests; the three gateway crates' suites (24 suites, 449 tests); clippy `-D warnings`; the dependency, layer and workspace-map checks.
- **Known limitations:** the rest of the stack under `rusty-mcp` is still `axum`, `jsonwebtoken`, `reqwest`, `tracing-subscriber` and OpenTelemetry (A6, second half). Nexus is frozen and outside the workspace; its `nexus-mcp` keeps its own `rmcp` dependency. The `rk-mcp` feature that is still named `rmcp` now only enables `rusty-mcp-client`. No real MCP client was run against any moved server.
