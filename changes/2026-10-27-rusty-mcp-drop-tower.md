## 2026-10-27 - rusty-mcp 0.12.0: the tower layers go (#886)

- **Why:** the layers existed for `agentgateway`, which since #1133 serves on `rusty_axum`. It used `LimitsLayer` only as configuration for `rusty_axum::Admission`, and called `McpMetricsLayer` through `tower_service::Service` by hand. Nothing else in the workspace used any of the three.
- **Removed:** `auth::RequireAuthLayer` and `auth::RequireAuth`, the `limits` module (`LimitsLayer`, `Limited`), and `otel::metrics::McpMetricsLayer`. The blocking `rusty_serve` adapters (`serve::AuthorizedHandler`, `serve::LimitedHandler`) stay and are now the crate's one adapter. There is no async auth adapter: an async server awaits `TokenValidator::validate` and checks the audience itself, as `agentgateway-auth` does. One can be added when a consumer needs it.
- **Changed:** `otel::metrics::McpMetrics` is a recorder rather than a tower service: `McpMetrics::new(instruments).with_known_names(..)`, then `start(method, name)` with the `Mcp-Method` and `Mcp-Name` header values and `RequestTimer::finish(status)` with the response status. The labels and the cardinality guard are unchanged. The header names are exported as `HEADER_MCP_METHOD` and `HEADER_MCP_NAME`.
- **Fixed:** a request whose handling is abandoned, for instance because the client hung up, now leaves `mcp.server.requests.in_flight` when its timer is dropped. The tower layer's future was dropped without decrementing it, so the gauge crept up with every abandoned request.
- **Changed:** `agentgateway` takes its limits as a `rusty_axum::Admission` (`serve::run`, `run_with_shutdown_and_limits`), and its MCP handler is a plain `McpService::call`. It drops `tower-layer` and `tower-service`; no tower crate is left in its build.
- **Dependencies:** `rusty-mcp` loses `http`, `tower-layer`, `tower-service` and `tokio` from `[dependencies]`, and `http-body` from `[dev-dependencies]`. Its entry in `PINNED_EXTERNAL_DEPENDENCIES` (`.github/scripts/check_workspace_deps.py`) is now empty. No dependency is added or bumped.
- **Tests:** the layer tests (`tests/authorization.rs`, `tests/limits.rs`, the in-crate `limits` and `auth/layer` tests) go with the layers; `tests/serve_adapter.rs` already covers the same refusals on the wire and gains the validator-outage case. `tests/otel_metrics.rs` drives the recorder, and `tests/trace_context.rs` serves the MCP handler on `rusty_serve`, so the axum test adapter in `tests/support` is gone.
- **Known limitations:** `tokio` is still compiled into the gateway, unused at run time: `rusty-mcp`'s `jwt` and `otel` features enable `rusty_request`'s `tokio` feature, so a JWKS fetch can run on a caller's tokio runtime. Dropping that needs `rusty-mcp`'s JWT tests moved onto `rusty_tokio` and is a follow-up. The gateway's integration tests still use tokio for their clients and mocks.
