## 2026-10-22 - rusty_tick: status, priority, tag and list filters in the web assistant

- **Added:** “high priority”, “what's high priority today?”, “overdue low priority tasks”, “tasks tagged work”, “#errands”, “overdue tasks with tag "deep work"” “what's in Work?”, “overdue tasks in the inbox list” and “high priority tasks tagged work in Home due this week” as well as “done tasks”, “completed tasks due this week”, “won't do tasks” and “open tasks due today”, become `filter_tasks {status?, priority?, tag?, list?, view}`, the view being all, today (overdue included, as in Today), next7 or overdue. A tag is “tagged X”, “tag X” or “#X”; a list is “in X”, “in list X” or “in the X list”, named as for “move … to list …”; quote either with spaces. A status is open (unless named), done (“done”, “completed”, “finished”, “closed”) or won't do; views go by due date for every status, so “done tasks due today” are done tasks that were due today. An “in” before a view (“due in the next 7 days”) stays filler. A message is read as a filter only when every other word is filler (“show me my … tasks”) or names one view, so “add buy milk high priority” still adds a task, “tag milk with work” still tags one, “done milk” still completes a task, and two views, statuses, tags or lists in one message are not guessed between.
- **Added:** `filter_tasks` is a browser tool over the UI's own views, with no MCP twin: `due_tasks` keeps the shape it shares with MCP, and an MCP agent filters `list_tasks` itself. A tag you do not have is named as such rather than answered with an empty list.
