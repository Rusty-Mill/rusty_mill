## 2026-10-23 - rusty_orch: cancel a hosted goal

- **Added:** `rusty_orch run <goal> --state <dir> --bbp <cfg> --cancel <reason>`. It takes the goal's assignment over at a new generation, so any earlier holder is fenced out, then cancels the BBP task of every Implement card through the new `TaskHost::cancel`. The host derives the task from its id rather than trusting the board, so work an open started before its handle was checkpointed is found; a task never opened is opened already cancelled, with nothing assigned or started. It returns only once `bbp quiesce` says nothing of the task runs, so the slot is free when the command returns. The card's execution is then recorded as cancelled and the assignment retired; a later `run` on that state is refused. Re-running the cancel completes an interrupted one and changes nothing after a complete one. New acceptance modes `orch-cancel`, `orch-cancel-moderator-lost`, `orch-cancel-mid-cancel` and `orch-cancel-unrecorded-open`.
- **Added:** `bbp quiesce --dir D --task T`: for an ended task, `true` only when no moderator, runner or harness group of it runs. On Linux every harness now gets a `bbp slot-hold` holder, with or without slots, and each holder's group is recorded by pid and start time, so `quiesce` can tell, and kill, what a dead moderator left.
- **Added:** BBP configuration `end_grace_secs`, passed to `bbp mod --end-grace-secs`, bounds how long a harness may keep running after its turn ends.
- **Known limitations:** Millboard is told the new generation, not the cancelled state: it has no operation for an execution's terminal state yet. A plain `run` after a cancel interrupted before retirement reports the BBP task's cancellation as a failure rather than finishing the cancel. `quiesce` and group records are Linux only, like sandboxed hosting. Path leases (3c) and fair admission (3d) are separate slices.
