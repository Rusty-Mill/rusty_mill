## 2026-10-21 - compile-at-floor CI job (issue #804)

- **Added:** the `msrv-compile` job in `ci.yml` (in `required-gate`'s `needs`) runs `.github/scripts/check_msrv_compile.py`. It groups the workspace members that declare a `rust-version` by major.minor floor, installs each floor's rustc, and runs `cargo check --locked --keep-going` (default features) on the group, with cargo from the pinned toolchain and `RUSTC` set to the floor's rustc. Cargo refuses a package whose `rust-version` is above that rustc, so a dependency over the floor fails too. Only the affected crates are checked on a PR, every crate on a full sweep; floors at the pinned toolchain, `rusty_multimodal_db` (its own msrv job) and the `remind_me` crates (their own jobs) are skipped. Builds go under `RUNNER_TEMP`, not the cached target directory.
- **Why not cargo at the floor:** cargo older than 1.85 cannot read this workspace's edition-2024 manifests. Current cargo also passes rustc flags an older rustc rejects, though they only affect lints: `--check-cfg` (needs `-Z unstable-options` below 1.80) and each dependency's `[lints]` table as `--warn=NAME` and the like (a lint newer than the rustc is error E0602; a cargo of the floor's vintage would not pass them). So every floor runs rustc through a small `RUSTC_WRAPPER` shell script that drops these flags; lints stay enforced at the pinned toolchain by the other jobs. 13 unit tests cover the grouping, the command and the wrapper (run against a fake rustc), and a workflow test covers the job's gating.
- **What it found, and the fixes:** a first run reported three failures. `rusty_log` (1.71) failed in `pin-project-lite` with `unknown lint: deprecated_safe`; that was the harness passing the dependency's `[lints]` to rustc 1.71, not a real requirement, and the wrapper now drops those flags. Its 1.71 stands: `log`, `proc-macro2`, `quote`, `syn` and `unicode-ident` declare 1.71, and with a matching cargo 1.71.0 the crate builds and tests with all features (rustc 1.70 compiles it with `--ignore-rust-version`, 1.69 fails in `proc-macro2`). `rusty_json` had no `rust-version` and uses `core::error::Error` (1.81); it now declares 1.81, which raises `orch-claude`, `orch-cli`, `orch-codex` and `orch-ollama` from 1.75 to 1.81. `rusty-whisper` had none and uses AVX-512 target features that are stable from 1.89; it declares 1.89, which raises `rusty_voice` from 1.88 to 1.89. `check_rust_versions.py` passes with these. After them every floor builds on Linux.
- **Not covered:** default features only, on Linux, so Windows-only code and optional features are not built at the floor. `inventory-tauri` (1.88) needs GTK system libraries that the CI image installs and that were not available when this was developed, so it was not compiled at 1.88 locally. The job builds from scratch each run (no cache of the per-floor target directories), so a full sweep is slow.
- **Closes:** the compile-at-floor part of #804.
