## 2026-10-21 - compile-at-floor CI job (issue #804)

- **Added:** the `msrv-compile` job in `ci.yml` (in `required-gate`'s `needs`) runs `.github/scripts/check_msrv_compile.py`. It groups the workspace members that declare a `rust-version` by their full declared version (`1.74` means `1.74.0`; a patch is kept), installs exactly that rustc, and runs `cargo check --locked` (default features) on **each member separately**, so one member's features are never unified into another's (for example `rusty_libc`'s no_std default is checked as declared, not with `rusty_confined_fs`'s `std`). Cargo comes from the pinned toolchain with `RUSTC` set to the floor's rustc. Cargo refuses a package whose `rust-version` is above that rustc, so a dependency over the floor fails too. Only the affected crates are checked on a PR, every crate on a full sweep. Versions at or above the pinned toolchain (compared as full versions), `rusty_multimodal_db` (its own msrv job) and the `remind_me` crates (their own jobs) are skipped. Builds go under `RUNNER_TEMP` and each version's build directory is deleted once checked.
- **Locked:** metadata is read with `cargo metadata --locked` and the job fails if `Cargo.lock` changed, so a lock nobody committed is never validated.
- **Why not cargo at the floor, and the wrapper:** cargo older than 1.85 cannot read this workspace's edition-2024 manifests, so the pinned cargo drives an older rustc through a small `RUSTC_WRAPPER` shell script. It drops what a newer cargo adds that an older rustc rejects and that cannot change whether the code compiles: `--check-cfg` (unstable before rustc 1.80) and the `--warn=`/`--allow=`/`--deny=`/`--forbid=` flags cargo derives from a dependency's `[lints]` table (for example `pin-project-lite`'s `deprecated_safe`; an unknown lint name on the command line is a hard error, E0602, in old rustc). Without this the job reported `pin-project-lite` as not building before 1.74; that was this harness, not the crate. 17 unit tests cover the grouping, exact versions, the per-member commands, the wrapper (run against a fake rustc), and a small real workspace in which a combined `-p a -p b` check passes while the per-member check of `a` correctly fails.
- **What it found, and the fixes:** `rusty_json` had no `rust-version` and uses `core::error::Error` (1.81); it now declares 1.81, which raises `orch-claude`, `orch-cli`, `orch-codex` and `orch-ollama` from 1.75 to 1.81. `rusty-whisper` had none and uses AVX-512 target features stable from 1.89; it declares 1.89, which raises `rusty_voice` from 1.88 to 1.89. `rusty_log` declares 1.71 (as set in #795): it builds there with default and all features, and below that cargo refuses `unicode-ident` (declares 1.71). `check_rust_versions.py` passes with these.
- **Checked locally, then in CI:** every version builds on Linux with this method except `sessionmgr-desktop` and `inventory-tauri` (1.88), which need GTK system libraries that the CI image installs and that were not available when this was developed.
- **Not covered:** default features only, on Linux, so Windows-only code and optional features are not built at the floor. The job builds from scratch each run, so a full sweep is slow.
- **Closes:** the compile-at-floor part of #804.
