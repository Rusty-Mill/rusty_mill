## 2026-10-23 - Patch tokio for RUSTSEC-2026-0386

- **Security:** tokio 1.53.1 let `tokio::io::unix::AsyncFd` constructors (`new`, `with_interest`, `try_new`, `try_with_interest`) accept any `T: AsRawFd`, violating I/O safety. The root `Cargo.lock` now pins tokio 1.53.3, which restores the `cargo-deny` advisories check on `main`.
- **Changed:** tokio 1.53.3 deprecates those constructors in favour of `unsafe fn AsyncFd::register`, which fails Clippy under `-D warnings`. The upstream-tokio call sites in `rusty_term` (PTY master read/write dups and `/dev/tty`), `ts-tun` and `ts-magicsock` now call `register`, each with a `SAFETY` note on why the descriptor stays open and unchanged for the `AsyncFd`'s lifetime. Registration errors still map to the same `io::Error`.
- **Known limitations:** Cargo also re-selected already-locked versions on existing edges: 21 `windows-sys` edges (Windows-only) and 3 `socket2` edges (`hyper-util`, `quinn`, `quinn-udp`, which also apply outside Windows). No package was added or removed. No independent proof of the upstream fix is claimed beyond the advisory, `cargo-deny` and Clippy and tests of the migrated consumers.
