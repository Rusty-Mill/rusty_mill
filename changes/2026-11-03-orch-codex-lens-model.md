## 2026-11-03 - rusty_orch: orch-codex answers lens questions

- **Added:** `CodexAgent` implements `orch_lens::Model` (Let Em Loose #594). Each question first proves a subscription login: `codex login status` must exit 0 and say `Logged in using ChatGPT`. An API-key login, no login, or anything else is `Unavailable`, nothing runs, and the probe's output (which can show part of a key) never reaches the error. `codex exec` then runs in its read-only sandbox with the scrubbed environment, the question's prefix and body on stdin, `--json` events on stdout and the last message to a scratch file. The reply must pass `orch_lens::parse` and report measured usage (at least one `turn.completed` event with integer input and output counts, cached no more than input), or the call is `Permanent`. A lens question runs in an empty scratch directory (with `--skip-git-repo-check`) unless the agent is built with `lens_read_only()`, which runs it in the repository root.
- **Changed:** `SCRUBBED_ENV` also removes `CODEX_API_KEY` and `OPENAI_BASE_URL`, for the dispatcher too. The `codex exec` argv is built from one shared base, so the dispatcher's argv is unchanged. `orch-codex` declares rust-version 1.89, the floor of `orch-lens`, and `rusty_json` moves from a dev-dependency to a dependency.
- **Known limitations:** nothing calls it yet. `codex exec` cannot bound its agent loop's tokens before the call, so this adapter is a flat-rate subscription provider only; the lens config refuses any nonzero price (ADR-0021). Codex has no tool-less mode: the empty working directory keeps the repository out of reach by default, but the read-only sandbox can still read elsewhere on the host, as it can for the dispatcher.
