## 2026-10-26 - rusty_a2a: a gRPC address with no scheme is TLS

- **Why:** the A2A spec says a gRPC interface URL is written `hostname:port` (`spec/a2a.proto`, `AgentInterface.url`), so an agent card that follows the spec gave `GrpcClient::from_agent_card` an address with no scheme. The `tonic` client parsed it and then failed its first call with "transport error"; since the move to `rusty_tonic` (stage B) it was refused up front. Neither dialled the agent. What the missing scheme should mean was left open; it is decided here.
- **Changed (`rusty_a2a`):** `GrpcClient::new`, `with_channel_options`, `from_agent_card` and `discover` read an address with no `://` as `https://`, verified against the operating system's trust anchors (or `ChannelOptions::connect.trust`), like any `https://` endpoint. Plaintext has to be written `http://host:port`. This fails closed: an agent that listens in plaintext on `localhost:50051` now gets a TLS-handshake failure (`UNAVAILABLE`) until its card says `http://localhost:50051`, and the request, with the caller's credentials, is never sent in the clear. A blank endpoint is still refused up front with a clear error.
- **Fixed (`rusty_http`):** `Url::parse` took `https://:50051` to have the host `":50051"` (the empty host fell through `parse_authority` as though the whole authority were the host) with the default port. It is now an `InvalidUrl` ("missing host"), as `https://` and `https:///x` already were. Found while making `:50051` a refused endpoint: with scheme-less addresses now accepted, it would otherwise have been dialled as a host called `:50051`. Nothing in the workspace writes a URL like that (searched).
- **Tests (written first):** `rusty_a2a/tests/grpc_client_transport.rs` (4, replacing one): an address with no scheme (`localhost:port` and an IP literal) reaches a TLS server whose CA is pinned; the same address on a plaintext server fails `UNAVAILABLE` and the request never arrives (a flag in the handler); an explicit `http://` is still plaintext; `""`, `"   "` and `":50051"` are refused with `GrpcConfig`. `rusty_http` `url::tests::rejects_a_port_with_no_host` (4 inputs, plus a bracketed IPv6 literal that still parses); `rusty_tonic` `an_unusable_url_is_invalid_argument...` gains two host-less URLs. The first two `rusty_a2a` tests and the `rusty_http` test failed before the change.
- **Known limitations:** `rusty_a2a`'s `server::push::tests::pinned_client_connects_to_the_validated_address_not_a_fresh_dns_lookup` needs DNS and fails in the sandbox, as on `main`. The server still does not terminate TLS, so an agent served by `serve_grpc` is reachable only at `http://`; put it behind a TLS terminator, and write its card accordingly.
