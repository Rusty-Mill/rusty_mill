## 2026-11-02 - rusty_mux terminal size, reset and theme (C40)

- **Added:** `terminal.size` reads a block's size as `COLSxROWS`, such as `80x24`.
- **Added:** `terminal.reset` resets a block's terminal by feeding it CAN, which ends any sequence its program left unfinished (a string, an escape waiting for its next byte, a cut CSI or UTF-8 character) without acting on it, then RIS: screen, scrollback, modes and colours go back to how they started. It needs the lease, and is refused while a client built before this change is attached to the block: such a client takes the CAN into an unfinished OSC string, so its copy would act on the string and miss the RIS. The attach client now advertises `TERMINAL_CONTROL` on its block connections to say it can be reset safely.
- **Added:** `terminal.set-theme` sets the default foreground, background and cursor colours and palette entries (`--palette N=COLOUR`), each `#RRGGBB` or `default`, as the program could with OSC 10, 11, 12 and 4. Programs that ask see the colours, and clients draw with them. It needs the lease, checks every colour before anything is sent, and is refused while the program's output has stopped inside an escape sequence.
- **Added:** `Features::TERMINAL_CONTROL` (bit 26). ctl and MCP refuse the three methods before sending anything to a server without it. The MCP tools for reset and theme attach and take the lease first, and `terminal.reset` is marked destructive.
- **Added:** `rusty_term_core::AnsiParser::ground`, whether the parser is between sequences.
- **Fixed:** rusty_term_core lets CAN and SUB abort an OSC string without acting on it, as they already did a DCS, APC, SOS or PM string. Before, they were taken into the OSC's body. They now also abort an OSC, DCS or APC string whose ESC was the last byte, where before they ended it and it was acted on (a title set, a clipboard write, a query answered).
- **Fixed:** the attach client draws the focused block's cursor colour (OSC 12) on the split screen, and puts the terminal's own back (OSC 112) when the focused block has none or the view changes, so no block inherits another's colour. Before, only a passed-through block's cursor took its colour.
- **Known limitations:** reset and theme are bytes in the block's output, so they reach every attached client and, when the attach client passes a block through, the person's own terminal; colours set that way stay in that terminal after detaching, as a program's would. A theme lasts until the program or a reset changes it. The attach client tells a chosen cursor colour from none by comparing it with the built-in default, so a cursor set to exactly `#ffffff` shows in the person's own terminal colour. A program that asked for mode 2031 reports is not told when the theme turns the background from dark to light. Tests run on Linux; Windows is checked by CI.
