## 2026-10-26 - Mill Board: rusty_tick as the card store (ADR-0012 step 3)

- **Added:** `--tick-url URL`, with the token read from the `RUSTY_TICK_TOKEN` environment variable only, runs the board over rusty_tick instead of `--store`. The board is the tasks tagged `agent`: column and claim are `board:`/`claim:` tags, the project is the task's list (the Inbox is `default`), comments are rusty_tick comments with their author, and dependencies, the forge link and the execution link are one `board` document per task. Every board write is one request fenced on the task version the board read, and every write moves that version, so the transition rules and the execution-binding compare-and-swap hold as before. A comment is an explicit append, so one the owner adds meanwhile is kept. An edit the owner makes in rusty_tick is what the board reads next.
- **Changed:** rusty_tick moves a task's version when a `board` document, or a comment written with `If-Task-Match`, is written for it, in the same locked step as the check, so the version names the task and its board document together.
- **Changed:** within a queue, `card_take` orders equal priorities by the manual order (rusty_tick's `sortOrder`) before age. A card imported from an issue gets an id derived from the issue number: a retried import never makes a second card, the sync skips an issue it imported before instead of failing, and an import interrupted before its link is relinked rather than exported as a new issue.
- **Known limitations:** with rusty_tick as the store, events are kept in memory only (a restart starts a new log), actor names must be lowercase, card tags come back lowercase, and `--backup-dir` is refused (rusty_tick holds the data). `card_plan` with both a priority and dependencies takes two requests there; if the second fails it reports an error with the priority applied, and the same plan again completes it. Import ids ignore the repository, so a board should sync one repository.
