## 2026-10-22 - rusty_tick: the MCP tools in the web assistant

- **Added:** besides adding tasks, the assistant understands:
  - “find …” (`search_tasks`)
  - “what's due today?”, “due this week” and “what's overdue?” (`due_tasks`)
  - “complete …”, “reopen …” and “delete …” (`complete_task`, `reopen_task`, `delete_task`)
  - “rename … to …”, “move/reschedule/postpone … to …”, and “make/mark/set … high/medium/low/no priority” or “set priority of … to …”, and “move … to list …”, “move … to the … list” or “move … to inbox” (`update_task`)
  - “lists” (`list_lists`)

  Each command is a frontend tool call that the browser runs against its store, named as the MCP server's tool. The server's tool table uses the same name constants, so the two cannot drift.
- **Added:** a task is named by its title: an exact title first, else the only title containing the words. When several match, the assistant lists them and asks; it never guesses. Completing considers open tasks only and reopening done ones only; the Trash is never searched.
- **Changed:** the assistant's add tool is now `add_task` (it was `create_task`), the MCP name. “What's due?” now reads every list through `due_tasks`, not only the view that is open, so the panel no longer sends the open view as context.
- **Added:** “rename … to …” and “move … to …” never guess where the name ends. A quoted name or new title is taken whole, “to” inside it included (“rename "buy milk" to "talk to mum"”). An unquoted rename needs exactly one “ to ”; with more, the assistant asks for quotes. A move cuts at the last “ to ”, since a day never contains one (“move talk to mum to friday”). The browser reads the day in your own time zone: today, tomorrow, a weekday (the next one, or a week on if it is today), in N days, next week, YYYY-MM-DD, or none to clear the dates. A timed task keeps its time of day, an undated one becomes all-day, and a start that would fall after the new due date is dropped. A day it can't read, or a blank title, changes nothing.
- **Added:** a move can name a time of day: “move … to friday at 3pm”, “tomorrow 9:30” or “2026-11-05 15:00”. A time alone (“3pm”, “at 9”, “noon”) keeps the task's day, or today for an undated task, and “all day” drops the time. A bare hour counts only after “at”, so “friday 3” isn't taken for 3 o'clock. An out-of-range hour or minute, or any unreadable part, changes nothing.
- **Added:** repeats: “repeat … every 2 weeks / daily / on weekdays / every monday and friday”, “make … repeat …” and “stop repeating …”. The task name ends at the last “every” or “repeat” outside quotes, or at a fixed how-often word. The browser turns the words into the app's repeat rule and checks it; an unreadable rule (“every blue moon”, an interval of 0 or over 99) changes nothing. As in the date picker, an undated task gets today's date when it starts repeating, and the reply says so. A monthly rule keeps the task's day of month, so a task due on the 31st returns to the 31st after February.
- **Added:** a priority phrase ends in a fixed word pair (“… high priority”), so the name before it can't be cut wrongly. In “set priority of … to …” the cut is at the last “ to ”, since a priority never contains one. Priority words are high, medium (or med), low, and none (or no); any other word changes nothing.
- **Added:** a move to a list is told from a move to a day by its destination clause alone, since a day never ends in “list”. A quoted task name ends at its closing quote. An unquoted name ends at the last “ to ” outside quotes whose rest is a whole list name (a list name containing “to” must be quoted). A command is only ever cut at a “ to ” outside quotes, so “to list” inside a title or a quoted list name is never taken for the destination: `move "Add to list groceries" to friday` still reschedules that task. The browser names the list as it names a task: an exact name first, else the only live list containing the words. An unknown, archived, blank or ambiguous list changes nothing.
- **Fixed:** the command words are matched case-insensitively in ASCII only, so a character whose lower case is longer (such as the Kelvin sign) can't shift where a name is cut.
- **Notes:** the assistant is still rule-based, not a model.
- **Added:** reminders: “remind me about … 1 hour before / a day before / at the time / on the day” and “stop reminding me about …”. The when is a fixed ending or the last two words before “before”, so the name is never cut inside. The browser writes the same trigger the date picker does (from the due time, or 09:00 for an all-day task) and keeps one reminder, as the picker does. An unreadable when, an undated task, or minutes or hours on an all-day task changes nothing. “remind me to …” still adds a task.
- **Added:** snooze: “snooze … for 30 minutes / 2 hours / a day / 1 week” and “snooze … until friday at 9”. Minutes and hours count from now (to the minute); days and weeks from the due day, or today for an overdue or undated task, keeping the time; “until” moves the task as “move … to …” does. Reminders count from the due time, so they move with it. An unreadable snooze changes nothing.
