## 2026-10-25 - agentgateway-mcp: the guardrail client on rusty_tonic (stage G2)

- **Why:** the last production use of `tonic`. `agentgateway-mcp` consulted its `ExtMcp` processors through a `tonic` client; stage G1 moved the messages, this moves the transport, now that `rusty_a2a`'s stage B has shown the `tokio` bridge. `tonic` is no longer in the normal dependency tree of `agentgateway` or `rusty_a2a` (`cargo tree -e normal -i tonic` finds nothing). What is left is test-only: `rusty_a2a`'s `tonic` oracle, `rusty_tonic`'s own oracle tests, and `rusty_tonic`'s optional `tonic-codec` feature that they enable.
- **Changed (`agentgateway-mcp`):** `wire::client::ExtMcpClient` is two unary calls over a `rusty_tonic::client::Channel` (no generic transport parameter, no `tonic` types); `Status` is `rusty_tonic::Status`. `Compiled::connect` builds a channel for the next endpoint of the ring with the processor's `timeout` as the connect limit, and connects on the call, as before (one connection per check; nothing is cached). Every other behaviour is kept: the per-call budget is still `tokio::time::timeout`, so a call that runs out is dropped and its HTTP/2 stream is reset; `failOpen`, the endpoint ring and the messages are untouched. `tonic` leaves the crate's dependencies and `rusty_tonic` is taken with `rusty-tokio` instead of `tonic-codec`.
- **Added (`rusty_tonic`):** `bridge::spawn(work) -> Result<Detached<T>, Status>` (feature `rusty-tokio`): runs `work` on a process-wide two-thread `rusty_tokio` runtime and returns a future any executor can await; dropping it aborts the work, and a panic is `INTERNAL`. It is the runtime and the abort-on-drop task that were private to `rusty_a2a`; `rusty_a2a`'s client bridge now uses it, so a process running both has one transport runtime, not two. Removed when the callers leave `tokio`.
- **Behaviour changes:**
  - A processor named `https://...` is verified against the OS trust anchors. The `tonic` client was built without a TLS feature and dialled it as plain TCP, so it spoke cleartext HTTP/2 to the port: it worked only against a server that was not speaking TLS, and failed against one that was. A configuration that relied on the first now fails closed (or open, with `failOpen`) like any unreachable processor. There are no TLS options for processors yet (OS trust only).
  - A reply's `grpc-status` is read from the trailers, where gRPC puts it. The three test processors (the `agentgateway-mcp` unit fixture and the ones in `agentgateway`'s `mcp_guardrails` and `mcp_span_attributes` tests) sent it in the headers beside a body, which `tonic` tolerated; a real server never does, and they now send trailers.
- **Tests (written first):**
  - `agentgateway-mcp` (3 new; the 120 existing guardrail tests pass unchanged against the new client): an `https://` processor is never sent the request in plaintext (failed before the change: the request arrived); a non-OK status from the processor is a failure that carries its message, and passes under `failOpen`; each phase calls its own RPC path (the fixture now records paths).
  - `rusty_tonic/tests/bridge.rs` (5): the result returns to a `tokio` caller, the work runs on the transport's runtime and not the caller's, 200 calls at once, dropping the wait cancels the work, a panic is `INTERNAL`.
  - The processor under test is the existing `axum` fixture, which shares nothing with either client; `rusty_tonic` has its own interop tests against a real `tonic` server.
  - 4 mutations: the `CheckResponse` path swapped (survived until the path test was added), the scheme ignored, no budget on `CheckRequest`, abort-on-drop removed from the bridge: all killed. A connect timeout that is not applied is not tested (it needs an address that drops packets).
- **Known limitations:** each check still opens a connection (kept to keep this change to the transport; a channel per endpoint would reuse them and `rusty_tonic` reconnects a lost one). `rusty_a2a`'s `server::push::tests::pinned_client_connects_to_the_validated_address_not_a_fresh_dns_lookup` needs DNS and fails in the sandbox, as on `main`.
