## 2026-10-14 - Library sources: index entries from other repos

- **Added:** `library/sources.json` lists repos whose skills (`SKILL.md`), mods (plugin folders) and root `prompts/*.md` the library indexes in place. `python3 library/build.py --sync` fetches each source (git over https, shallow, into the git-ignored `.cache/`) and builds; plain `build.py` stays offline and warns about any unsynced source; `--strict` fails on warnings. New modules: `fmt.py` (parsing/reading, moved out of `build.py`) and `sources.py` (validation, sync, scan).
- **Added:** computed provenance `github.com/<repo>@<sha>:<path>` on every remote entry, the repo name as a tag, a "From <repo>" label on cards, remote install commands for mods that fetch the exact indexed commit (full SHA, built in Python and quoted for bash/zsh and PowerShell), and "By source" grouping by `repo@sha`.
- **Added (pilot):** `baileyrd/my_claude_mods` pinned at `e8a8914`: 23 mods, no warnings. The page grows from about 0.2MB to 1.3MB because mod README and hook sources are embedded.
- **Security:** remote content is only read as text and never executed. Symlinks are not followed and every file read for a mod must resolve inside the mod folder (a hostile repo cannot make the page embed other files, including through a symlinked `hooks` directory, whose children look like ordinary files). Well-known build/test folders are skipped, sizes are capped with a visible marker, a source cannot set `featured` or `status`, and `repo`, `ref` and `name` are validated (no leading `-`, no `..`, https and github.com only). Every value taken from a source is type-checked at ingestion (strings, lists of strings, no control characters, length caps); malformed entries are skipped with a warning. Install commands are built in Python, not in the page: every argument is quoted as data for bash/zsh and PowerShell, a path that cannot be quoted safely (including the typographic quotes PowerShell treats as quote characters) gets no command, and the command fetches exactly the indexed commit (full SHA) rather than the default branch, into a new directory (it refuses an existing one) and stops at the first failing step in bash/zsh and PowerShell. The cache records the repo and ref it was fetched for, and a build refuses a cache that does not match `sources.json`, is symlinked, or whose worktree differs from its commit (modified, untracked or ignored files). `--sync` fetches into a fresh directory it creates and replaces `.cache/<name>` only if that is an untouched checkout from a previous sync; symlinks, foreign directories and modified checkouts are refused and left alone, and nothing is cleaned in place.
- **Verified (run):** 56 library unit tests; the generated bash line run through `sh` with stub `git`/`claude` binaries for hostile paths (`$(touch …)`, backticks, quotes, spaces; nothing executes and the path arrives as one argument), for a failing init/fetch/checkout (the launcher is never reached) and for an existing directory (nothing runs); a checkout test showing the command lands on the reviewed commit after the default branch moves on; a real `--sync` from GitHub at the pinned SHA (1.3s); headless Chromium over the 36-entry page (repo tag filter, card label, provenance, install hint, hook source, one "By source" group of 23, no page errors, stable over three runs).
- **Known limitations:** The network step of `sync` is not unit-tested (the rest of `sync`, including the safety rules, is, with a local commit standing in for the fetch); it was run for real against the pilot before the last rounds of changes. The PowerShell command is checked structurally and against a model of its tokenizer, not executed (no PowerShell in CI or the authoring environment). Only GitHub is supported. A plugin's bundled skills are part of the plugin, not separate entries. `CLAUDE.md`/`AGENTS.md` sections are not indexed from sources. Hooks of third-party mods are embedded for reading but never reviewed by the library; they run unsandboxed once installed. CI runs the offline build only, so it does not exercise `--sync`.
