## 2026-10-21 - rusty_tonic: the gRPC client (phase 4b-2)

- **Why:** phase 4b-2 of the first-party `prost`/`tonic` plan. The sans-IO core (4b-1 of `rusty_tonic`) has the protocol; `rusty_hyper` has the transport. This joins them into the thing a service calls. The design was approved before any code (streaming types without a `Stream` trait, lazy connect with one transparent retry, a missing `grpc-status` is `UNKNOWN`, the client in `rusty_tonic` behind `rusty-tokio`).
- **Added:** `rusty_tonic::client`, behind the `rusty-tokio` feature (a default build is unchanged).
  - `Channel::new(url, ChannelOptions)` (cloning shares one connection) and four calls: `unary`, `server_streaming -> Streaming`, `client_streaming -> (Sender, Reply)`, `bidirectional -> (Sender, Streaming)`. Messages are `rusty_prost::Message`. `Request { message, metadata, timeout }` and `Response { message, metadata, trailers }`.
  - `ChannelOptions`: the `rusty_hyper::ConnectOptions` (TLS trust, a client certificate, timeouts, keepalive), a channel deadline (the shorter of it and the call's applies; sent as `grpc-timeout` with what is left at send time and enforced locally, resetting the stream on expiry), receive limit (4 MiB, over it is `RESOURCE_EXHAUSTED`), send limit (unlimited; over it fails before anything is sent), `user-agent`, and an `Interceptor` that may change a call's metadata or refuse it with a status.
  - The connection is opened by the first call and reopened after it is lost. A call that finds the connection closed or going away, so nothing was sent, is tried once more on a new one; a call that reached the server is never repeated. No backoff.
  - Statuses: trailers (and "trailers-only" responses) are the call's status; a missing `grpc-status` is `UNKNOWN`; a message cut short or a second message in a unary reply is `INTERNAL`; an HTTP/2 reset maps by reason (`REFUSED_STREAM`, `GOAWAY` and transport errors `UNAVAILABLE`, `CANCEL` `CANCELLED`, `ENHANCE_YOUR_CALM` `RESOURCE_EXHAUSTED`, `INADEQUATE_SECURITY` `PERMISSION_DENIED`, the rest `INTERNAL`); a connect failure is `UNAVAILABLE`, an unusable URL `INVALID_ARGUMENT`.
  - Dropping a `Streaming`, `Reply` or `Sender` before the call ends cancels it (RST_STREAM `CANCEL`).
- **Changed (`rusty_hyper`):** `ConnectOptions` and `ClientIdentity` are `Clone`, so a channel can reconnect with the options it was given.
- **Tests (written first; all failed on `todo!()`):** `tests/client_calls.rs` (14: every call shape against a scripted server, the misbehaving-server table, limits, interceptor, URL and refused connection), `tests/client_lifecycle.rs` (14: deadlines on the wire and local, cancellation on drop, one shared connection, the stream limit, reconnect, retry once, never twice, a connection dying under a call), `tests/client_tls.rs` (3: https, an untrusted server, mutual TLS) and `tests/client_tonic.rs` (5: a real `tonic` server on tokio — every call shape, an error with metadata, an unimplemented method), plus the error-mapping table as unit tests. Run 60 and 40 at a time in parallel for load, and 15 mutations of the implementation (retry, deadline choice, send limit, cut messages, cancellation on drop, error mapping, interceptor): the survivors were closed with tests (a message cut short under OK trailers, dropping a server stream); three remain (a non-`NO_ERROR` send failure ignored, an I/O error not retiring the connection, `GOAWAY` not retried) because the connection-level paths they guard are exercised only through the equivalent `Closed` path.
- **Dev-dependencies:** `tonic` (with `router`), `tonic-prost`, `prost`, `tokio`, `http`, `tower`, `futures-util` as the oracle server (never shipped), `rcgen` and `rustls` for certificates.
- **Known limitations:** no compression (a compressed reply is `UNIMPLEMENTED`), no load balancing or multiple endpoints, no backoff, no per-call `authority` override. A `Sender` that is not used again keeps the stream open until it is dropped, even after the call's deadline passed on the reading side; its next `send` then fails.
- **Depends on:** #826 (`rusty_hyper`), and through it #822 and #828.
