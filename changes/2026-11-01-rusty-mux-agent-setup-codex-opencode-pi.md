## 2026-11-01 - rusty_mux: agent setup for Codex, OpenCode and Pi

- **Added:** `rusty-mux-ctl agent setup|status|remove` takes `--agent claude|codex|opencode|pi|all` (repeatable; Claude Code when none is named, as before), `--project` (every file under the current directory) and, for setup and remove, `--dry-run` (checks every file and writes nothing). Codex gets the same `SessionStart` hook as Claude Code in `hooks.json` (`$CODEX_HOME` or `~/.codex`), restored byte for byte on remove; OpenCode gets a plugin and Pi an extension, each one generated file that runs `agent hook` by absolute path and adds its text to the system prompt. The three share one skill in `~/.agents/skills/rusty-mux/`, kept on remove while another of them still has its hook. Each line of output now names its agent (`"agent"` in `--json`), and `status` reports `unreadable` for a file it cannot read or edit instead of failing. Thirteen new tests in `ctl/src/agent/tests.rs` and one rewritten parser test (C39).
- **Known limitations:** Codex skips a new or changed hook until it is trusted with `/hooks`. The OpenCode plugin uses `experimental.chat.system.transform`, which OpenCode may change. The plugin and extension were run against stand-in harnesses in Node, not inside OpenCode or Pi, and the Codex and Windows paths were not run. On Windows, Codex's hook command is quoted for a POSIX shell, as Claude Code's is; whether Codex runs it there is unchecked. A hook written with `--project` names this machine's ctl, so it does nothing for someone else who checks it out.
