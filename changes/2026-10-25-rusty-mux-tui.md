## 2026-10-25 - rusty_mux throwaway TUI

- **Added:** `crates/apps/rusty_mux/crates/tui` (`rusty_mux_tui`, binary `rusty-mux <socket> [block]`). Without a block id it creates a session, window and block; it negotiates `CHECKPOINT_V2`, attaches, takes the input lease, sizes the block to the local terminal, assembles the RTCP v2 checkpoint with `rusty_mux_server::checkpoint::Receiver`, paints its grid once at Ready and then passes raw output to the local terminal. Ctrl-] detaches and prints the block id for reattaching. Two blocking threads, no async runtime. The client exits when the block closes, the server goes away or the keyboard ends, not only on Ctrl-]: the input loop polls the keyboard and stops once the output side has ended. On every exit it shuts the stream, joins the output thread, then resets the modes a program may have set (alternate screen, cursor visibility, keypad, bracketed paste, mouse and focus reporting, style) before leaving raw mode. `tests/lifecycle.rs` drives the binary in a pty against a scripted server for the closed, view-only and detach-after-modes paths.
- **Known limitations:** throwaway by design (Phase 2 brings real clients). Linux only, no local resize tracking, only colours are painted from the checkpoint (no bold or underline), and a client without the lease is view-only. The checkpoint's parser and input modes stay in the client: the local terminal starts from its own state, so output that continues a sequence begun before attach, or relies on modes set before it, can draw differently until the program redraws.
