## 2026-10-10 - rusty_bbp_host: the sandboxed runner can build Rust (proving-run root cause)

- **Fixed:** the first proving run (`docs/proving/2026-10-09-slug-1.md`) escalated because every sandboxed run failed to start `rustc`. Root cause, reproduced with `strace` under the helper: `openat("/dev/null")` returned `EACCES` inside the sandbox, and Rust's std opens `/dev/null` in the child for a null stdio before `exec`, so cargo's spawn of rustc failed before rustc existed. Behind it: no writable `TMPDIR` for the linker, and Landlock `EXDEV` on rustc's cross-directory `.rmeta` rename. The runner now grants `/dev/null` read-write and a per-run scratch directory as `TMPDIR`; `platform-linux` 0.27.3 queries the Landlock ABI and handles and grants `REFER` on writable roots on ABI v2+ kernels. A sandboxed `cargo test --offline` of a small crate passes end to end on a Landlock ABI 7 kernel.
- **Security:** the scratch directory `run-N.tmp` is created exclusively under the work root for each execution, mode `0700`: a symlink at that path is refused (its target would otherwise become a writable sandbox root), a stale directory from an earlier attempt is removed first so nothing carries over, and the created path is re-checked and canonicalised to sit directly under the work root. The sandbox helper opens granted paths by name, so the runner also requires the work root to be owned by its own user and writable by nobody else, which closes the check-to-grant window to the moderator's user, already trusted with the task directory. Regression tests cover a symlink to an outside sentinel (run reported `error`, nothing executed, sentinel untouched), a stale directory (replaced) and a world-writable work root (refused).
- **Added:** `runner_e2e` test for null-stdio spawn, cross-directory rename and `TMPDIR` under the real sandbox; `platform-linux` re-exec test for cross-directory rename and link inside a writable root, asserting success on ABI v2+ and refusal on ABI v1.
- **Changed:** PAL group bumped to 0.27.3 (behaviour only); the host README and the proving runbook describe the runner's grants and the `CARGO_HOME` symlink pitfall from the record.
- **Known limitation:** `/etc/ld.so.cache`, `/proc/self/*` and `/dev/urandom` are still unreadable in the sandbox; cargo and rustc fall back (default library paths, `getrandom`) and the build succeeds, but a toolchain that insists on them would need `read_roots` entries.
