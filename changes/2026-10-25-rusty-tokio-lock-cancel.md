## 2026-10-25 - rusty_tokio: cancellation-safe Mutex and Semaphore waiters (#1064)

- **Fixed:** `sync::Mutex` handed its release to a cancelled waiter's dead waker, so the next live waiter slept until an unrelated `lock()` came along. Each waiter now holds a place in the queue, as `RwLock`'s do. A dropped `lock()` future leaves the queue, and a dropped front waiter passes its wake to the next one. A re-polled waiter refreshes its waker instead of queuing it again.
- **Fixed:** `sync::Semaphore` had the same defect, with worse effects. A dropped queued `acquire()` stayed at the front of the FIFO queue and blocked every waiter behind it. Once a release granted it permits, those permits were lost for good. A dropped claim now leaves the queue, or hands back permits it was granted but never took, and then grants the waiters behind it. `close` now sets each waiter's outcome while it holds the state lock, so a claim's outcome is final when its drop reads it.
- **Fixed (review):** the new cleanup and waker-refresh paths dropped a removed or replaced `Waker` while holding the internal state lock. A waker's destructor can re-enter the primitive, for example by calling `try_lock` or `add_permits`, and that deadlocked. Such wakers are now moved out under the lock and dropped after it is released. Two bounded regression tests use re-entrant waker destructors; both deadlocked before this fix.
- **Fixed (review):** the new `Mutex` release and pass-on cloned the queued `Waker` while holding the state lock. A custom `RawWaker`'s clone callback may re-enter the mutex, and that deadlocked. Queued `Mutex` wakers now sit behind an `Arc`, so a handoff copies a refcount and runs no waker callback. A waiter's own clone is now made before it takes the lock, in both `Mutex` and `Semaphore`. Two bounded regressions use a clone callback armed after enqueue; both deadlocked before this fix.
- **Changed:** both modules recover a poisoned inner `std::sync::Mutex` instead of calling `unwrap`. No code that can panic runs while it is held.
- **Checked:** `RwLock` was already cancellation-safe (#1024).
- **Verified:** `tests/lock_cancel.rs` has 13 hand-polled tests with no sleeps. They cover a cancelled head waiter, a head waiter cancelled after its wake, a cancelled middle waiter, a re-polled waker, a cancelled large semaphore head, a granted-then-dropped claim and `close`. On `main`'s code, 8 fail. Disabling the pass-on in `Mutex` or the permit return in `Semaphore` each fails its test. `cargo test -p rusty_tokio -p rusty_tokio-macros --all-features`, clippy `-D warnings`, fmt and `cargo test -p rusty_tonic` pass.
