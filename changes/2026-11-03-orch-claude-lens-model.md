## 2026-11-03 - rusty_orch: orch-claude answers lens questions

- **Added:** `ClaudeAgent` implements `orch_lens::Model` (Let Em Loose #594). Lens questions are refused as `Unavailable` unless the agent is built with `lens_no_overage()`, the operator's assertion that the account cannot bill beyond its plan (usage credits or extra usage disabled); nothing in the adapter can verify that. Each question then checks the auth method: `claude auth status` must exit 0 and report `authMethod` `claude.ai` or `oauth_token` (`SUBSCRIPTION_AUTH`). Any other method, an unknown one or none reported is `Unavailable`, and nothing runs. `claude -p` then runs with the question's prefix as the whole system prompt and its body on stdin, in the repository root with the scrubbed environment. A lens question runs with `--tools ""` unless the agent is built with `lens_read_only()`, which gives the usual `Read,Grep,Glob`. The reply is refused as `Permanent` if it is not UTF-8, does not pass `orch_lens::parse`, or does not report `input_tokens` and `output_tokens` as counts. Usage counts fresh input, cache writes and cache reads as input, cache reads as cached.
- **Changed:** `SCRUBBED_ENV` also removes `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CODE_USE_ANTHROPIC_AWS` and `CLAUDE_CODE_USE_MANTLE`, for the dispatcher too. The `claude -p` argv is built from one shared base, so the dispatcher's argv is unchanged.
- **Changed:** `orch-claude` now declares rust-version 1.89, the floor of `orch-lens` (via `rusty_bbp`).
- **Known limitations:** nothing calls it yet. `claude -p` cannot bound an agent loop's tokens before the call, so it runs only at zero price (the lens config refuses any other, ADR-0021). The login check establishes the auth method, not billing; whether a call can be charged rests on the operator's assertion, which runtime approval must verify against the account. A usage check after the call is an acceptance check, not a spending bound.
