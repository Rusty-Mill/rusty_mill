## 2026-10-21 - rusty_a2a: the gRPC messages on rusty_prost (stage A)

- **Why:** stage A of moving `rusty_a2a`'s gRPC binding off `prost`/`tonic` (the plan's phase 5c). The design was approved before any code: this stage replaces the messages and leaves `tonic` as the transport; stage B (the transport on `rusty_tonic`) is a separate design check, because `rusty_a2a`'s engine needs a `tokio` context (`tokio::spawn`, `tokio::time`) that `rusty_tonic`'s `rusty_tokio` runtime does not give, and `axum` and `reqwest` already bring `hyper`/`h2` into the same crate.
- **Changed:** `rusty_a2a::pb` (feature `grpc`).
  - The 44 messages and 2 enums of the vendored `spec/a2a.proto` are written out as `rusty_prost::Message` impls in `src/pb`, from a field table (`message!`/`oneof!` in `src/pb/macros.rs`): one line per proto field, with a *kind* (`string`, `msg`, `rep_msg`, `map_msg`, ...) that says how it goes on the wire. The shapes follow what `prost` generated, so `grpc_convert.rs` changed only where the types do: message fields are `Option<M>`, enum fields are their `i32` (an unknown value is kept; `TaskState`/`Role` have `TryFrom<i32>`, `as_str_name`, `from_str_name`), `oneof`s are `Option` of an enum in a module named for the message (`part::Content`), `optional` scalars are `Option`s, maps are `BTreeMap` (sorted, so encoding is deterministic), `google.protobuf.Struct`/`Value`/`Timestamp`/`Empty` are `rusty_prost::wkt`.
  - `pb::a2a_service_server` (the `A2aService` trait, `A2aServiceServer`) and `pb::a2a_service_client` (`A2aServiceClient`, `with_interceptor`) are written by hand on `tonic::server::Grpc` and `tonic::client::Grpc`, with a small `tonic` codec over `rusty_prost`. The names and signatures are those `tonic-prost-build` generated, except that `DeleteTaskPushNotificationConfig` returns `pb::Empty` instead of `()`.
  - `google.rpc.ErrorInfo` details use `rusty_prost::rpc` and `tonic::Status::with_details` instead of `tonic-types`.
- **Removed:** `build.rs`, the `protoc` requirement (also from the crate's own CI workflow and its docs), and the dependencies `prost`, `prost-types`, `tonic-prost`, `tonic-types`, `tonic-prost-build`. Added: `rusty_prost` and `bytes` (already in the tree), both under `grpc`.
- **Breaking (`rusty_a2a::pb`):** the types no longer implement `prost::Message`, and the service server and client are the hand-written ones above. Nothing else in the crate's public API changes. The crate is unpublished (0.1.0).
- **Tests (written first; they did not compile against the generated types):** `tests/pb_wire.rs` (14) checks the messages against 286 vectors in `tests/golden/a2a_vectors.json` made by Google's Python protobuf runtime (`tests/golden/gen_vectors.py`): for each of the 44 messages an empty message and five random ones built from the descriptors (every oneof arm, maps, unicode, large and negative integers, unknown enum values), plus hand-built edge cases (unknown fields, a scalar repeated, fields out of order, sub-messages and oneof members repeated, map keys repeated or missing, an optional scalar set to zero). Each must decode and re-encode to the reference's bytes, and again from those bytes. Also: every prefix of every vector, bad UTF-8, a length past the end, nesting past the depth limit, and random bytes through every message decode without a panic. 15 mutations of the table macros and the glue (each field kind written at its default, the map key, oneof merging, repeated order, optional zero and negative, a wrong field number, the unknown-enum check, the error `domain`): two survivors were dead code (an unused `bytes` field kind, an ignored return value in the oneof reader), removed; two gaps got tests (negative enum values, the error domain); two remain, equivalent by construction. The 57 gRPC tests and the rest of the crate's suite pass unchanged (214 pass; the one failure, `server::push::tests::pinned_client_connects_to_the_validated_address_not_a_fresh_dns_lookup`, is a DNS lookup that fails in the sandbox and fails the same on `main`).
- **Finding:** the reference's "deterministic" map order is stable but not byte order (it puts the key `aa` before `a`), and the wire format leaves map order open. The vectors keep several-entry maps to same-length keys, and odd keys (empty, unicode, long) to maps of one.
- **Not included:** stage B (the transport), `agentgateway-mcp`'s own `prost`/`tonic` use, a generator for the table.
