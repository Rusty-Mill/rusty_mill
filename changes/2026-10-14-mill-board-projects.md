## 2026-10-14 - Mill Board: projects

- **Added:** cards belong to a `project`; `--projects FILE` names the projects and the repository paths each may change, grouped by repository (`{"repos": {...}}`; a flat file is one repository; every repository has a project named like itself that owns the rest). Project names are unique across repositories. `board_projects`, `board_owns` (which of some paths a project does not own, answered from the whole registry so a limited runner cannot miss a sibling's files), `card_assign` (Triage; drops the claim), a `project` argument on `card_add`, `card_take` and `board_list`, and a two-pane side panel in the UI: repositories with counts and, for the chosen one, its projects, plus an Agents list (claim holders and their counts) that filters by claimant; each agent has its own colour, applied to the cards it holds (a dot pulses while the card is in building, qa or review). A credential in `--identities` can carry `"projects": [...]`: it cannot see, take or change other projects' cards. The check is inside every write's compare-and-swap, so a card re-assigned mid-call is refused. Cards stored before this read as `default`; the record layout is unchanged.
- **Runner:** `mill-runner --project NAME` (required on a multi-project board) only takes that project's cards and, after a stage succeeds, discards the whole run and fails the stage if it changed a path outside the project's paths or `--shared-path` (default `changes`, `Cargo.lock`). The sandbox write scope is still the worktree; paths are enforced at commit.
- **Settings:** a ⚙ view to add and remove agents (credentials; the token is shown once; rotate), edit repositories and projects, edit roles, and configure the GitHub sync, behind a new `admin` capability (held by `human`). `--settings-dir DIR` (or `--identities`, `--projects`, `--roles`, `--github-config`) names the files it edits in place: validated, written atomically (secrets owner-only) and applied live, the sync restarting on a change. A first start creates an `admin` credential and prints its token once. Refused: anything that leaves no admin, drops a role an agent has, or drops a project that has cards. Settings are `POST /api/settings_*` only, not MCP tools. ADR-0004.
- **Tests:** `tests/projects.rs` (scope on every write, `take`, `assign`, a re-assignment race), the operation table with a limited credential, runner scope and discard against a scripted workspace, `git status` parsing and discard against real git, `tests/ui/projects.mjs` (the side panel, two repositories) and `tests/ui/settings.mjs` (the settings view) in headless Chromium; `tests/settings.rs` over a socket (the admin gate, live effect, files, no lock-out, secrets never listed), each guard removed in turn and a test failed. Every enforcement check was removed in turn and a test failed.
- **Known limitations:** open and shared-token boards still trust claimed actors. `board_events` shows other projects' event metadata (no card text). GitHub sync is project-blind. ADR-0003.
