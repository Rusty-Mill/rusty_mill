## 2026-11-15 - ts-daemon hub: the launcher (mesh hub slice H6)

- **Added:** `rusty-mux-server --hub ...` takes the same flags and runs the hub (build with `--features hub`; off by default, so the default server build gains no dependency) instead of a mux server (no sessions, no socket; D245). Both launchers share `ts_hub::launch`. With the feature on, the server opens no socket unless `--hub` is given, so the egress audit (#266) is unaffected. Linux only.
- **Added:** `ts-daemon hub --listen ADDR:PORT [--tls-cert PEM --tls-key PEM] [--stun ADDR:PORT] [--state-dir DIR] [--node-ttl SECS] [--keys FILE] [--policy FILE] [--advertise HOST]`. The hub's Noise identity and node table persist in `--state-dir` (`NodeState` and `FileStore`), so a restart keeps its nodes, spent keys and bans. With the TLS pair it serves `Hub::serve_tls`; a bad certificate, key, keys file or policy file stops it before it serves anyone.
- **Added:** the keys file (`KEY LOGIN [reusable] [name=SERVER]` per line; `ts_hub::parse_keys`, `Hub::load_keys`). It must not be readable by group or others. Errors name a line number, never the line. The file owns the keys it lists (`NodeStore::set_file_keys`, saved with the key): one removed from the file stops registering anyone at the next load, also if it was removed while the hub was down (nodes already registered stay). A load is all or nothing. To change a listed key's settings, drop it, reload, then list it again.
- **Added:** SIGHUP re-reads the policy and keys files; a keys or policy file that does not parse or is refused leaves the old keys and policy both in force. If the listener fails the hub exits non-zero instead of idling; `--help` exits 0.
- **Changed:** re-adding a pre-auth key that already exists with the same settings is a no-op and keeps its spent mark (a restart reading the same keys file used to be able to unspend a single-use key); with other settings it is refused (`InvalidKey`). Before, `add_preauth` silently replaced the record.
- **Logs:** addresses, the hub's public key and counts; no keys, tokens or relayed bytes.
- **Not in this slice:** running the hub *inside* a serving mux server (`--hub` is a mode of its own, like `--login`); a `config.json` section (flags and two files only); the Windows/macOS launcher; the spike-B transfer test through `ts-net` (needs #1466); stock `tailscaled` interop.
- **Tested:** `rusty-mux-server --hub` serves `GET /key` and refuses a bad flag; the real `ts-daemon hub` binary: two nodes join with a keys-file key and move 1 MiB through its DERP relay byte for byte; SIGHUP adds `k2` and drops `k1` without a restart; a world-readable keys file and a bad certificate each stop it before it serves; argument parsing; keys-file parsing and reload (spent marks survive, a file that does not parse changes nothing).
