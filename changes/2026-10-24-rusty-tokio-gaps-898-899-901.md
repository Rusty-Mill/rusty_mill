## 2026-10-24 - rusty_tokio: const Mutex, time::Instant, macro flavors, CancellationToken (#898, #899, #901)

- **Added:** `sync::Mutex::const_new`, a `const fn`, so `static M: Mutex<T> = Mutex::const_new(..)` builds (#898, gap G2).
- **Added:** a public `time::Instant` with tokio's surface (#898, gap G3). It has `now`, `from_std`, `into_std`, `duration_since`, `checked_duration_since`, `saturating_duration_since`, `elapsed`, `checked_add` and `checked_sub`. It implements `Add`/`Sub`/`AddAssign`/`SubAssign<Duration>`, `Sub<Instant>`, both `From` conversions with `std::time::Instant`, and `Ord`/`Eq`/`Hash`/`Debug`/`Copy`. `now()` reads the runtime's clock, so with the clock paused it moves only by what `time::advance` moves it. Outside a runtime it reads real time.
- **Added:** the paused clock now auto-advances, as tokio's does. On a current-thread runtime, the clock jumps to the next pending timer when `block_on`'s future was not woken, no task is runnable and no `spawn_blocking` job is in flight. Timers whose `Sleep` was dropped are skipped. Without this, `start_paused` could not work.
- **Added:** `#[rusty_tokio::main]` and `#[rusty_tokio::test]` accept `flavor = "multi_thread"`, `flavor = "current_thread"` and `start_paused = bool`, alongside `worker_threads` and `flavor = "thread_per_core"` (#899, gaps G4 and G5). As in tokio, `worker_threads` with `current_thread`, `start_paused = true` with any other flavor, an unknown flavor or argument, and a repeated argument are compile errors.
- **Added:** `sync::CancellationToken` with tokio-util's API (#901, gap G8). It has `new`, `cancel`, `is_cancelled`, `cancelled`, `cancelled_owned`, `child_token` and `drop_guard`, plus `DropGuard::disarm`, `Clone`, `Default` and `Debug`. Also exported: `DropGuard`, `WaitForCancellationFuture` and `WaitForCancellationFutureOwned`. A child holds its parent strongly and the parent holds the child weakly. A dropped child unlinks itself, and a dropped `cancelled()` future removes its waker, so neither piles up on a long-lived token. No lock is held while waking or dropping.
- **Changed:** the time API now uses `time::Instant` instead of `std::time::Instant`, as tokio's does. This covers `sleep_until`, `timeout_at`, `interval_at`, `Sleep::deadline`, `Sleep::reset`, `Interval::tick`, `Interval::poll_tick` and `Interval::reset_at`. This is a breaking change for callers that pass a std `Instant`. The in-repo callers are updated: `rusty_axum` (`serve.rs`), `rusty_hyper` (`server.rs`) and `rusty_tonic` (`client/streaming.rs`, converted with `.into()`).
- **Changed:** the macro docs no longer say there is no pausable clock (#56). The README and ARCHITECTURE non-goal are updated to match.
- **Verified:** new tests in `tests/pause.rs` (Instant and auto-advance, including the `spawn_blocking` hold-off), `tests/main_test_attrs.rs` (flavor, worker count and `start_paused`) and `tests/cancellation_token.rs`. A static `const_new` mutex test is in `tests/sync.rs`. Unit tests check that a token's child and waiter maps drain. Compile-fail doc-tests cover the rejected macro arguments, each paired with a passing case. `cargo test -p rusty_tokio -p rusty_tokio-macros --all-features`, clippy `-D warnings`, fmt and `cargo check` for `x86_64-pc-windows-gnu` pass. So do the `rusty_axum`, `rusty_hyper` and `rusty_tonic` tests, and `cargo check --all-targets` passes for every workspace crate that depends on `rusty_tokio`.
- **Known limitations:**
  - With no `flavor`, `#[rusty_tokio::test]` still builds the multi-threaded runtime, which differs from `#[tokio::test]`. The exception is `start_paused = true` without a flavor, which selects `current_thread`.
  - Auto-advance runs only in a current-thread `Runtime::block_on`, not in `LocalRuntime::block_on` or `LocalSet::run_until`.
  - Real I/O still arrives in real time, so a paused test that races I/O against a timeout can see the timeout win.
  - `CancellationToken::run_until_cancelled` and `drop_guard_ref` are not provided.

- **Review corrections:** cancellation serializes overlapping subtree propagation and publishes completion after descendants; RawWaker clone/drop callbacks run outside locks with a completion recheck. Paused-clock idle checks observe blocking completion before rechecking runnable continuations. Deterministic lock/channel synchronization and reentrant RawWaker regressions cover these boundaries. LocalRuntime/LocalSet exclusions and clock resume behavior are unchanged.
