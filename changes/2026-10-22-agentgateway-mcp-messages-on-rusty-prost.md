## 2026-10-22 - agentgateway-mcp: the guardrail messages on rusty_prost (stage G1)

- **Why:** phase 5 of the `prost`/`tonic` replacement. The gateway wrote its eight `ext_mcp` messages with `prost` derives and spoke gRPC with `tonic`; the messages move, the transport does not (stage G2 waits with `rusty_a2a`'s stage B for the rest of the crates to leave `tokio`). Stacked on the `rusty_prost` declaration macros.
- **Changed (`agentgateway-mcp`):** `guardrails/wire.rs` declares the messages with `message!`, `oneof!` and `open_enum!`, one line per field with its number, the same public names (`request_result::Result`, `authorization_error::Code`, and so on; `Pass` is now exported). `Struct` metadata is `rusty_prost::wkt::Struct`, so `to_proto_value` returns a `wkt::Value` and `proto_to_json` no longer returns an `Option` (a `Value` always has a kind). The client is the same two unary calls over `tonic::client::Grpc`. `prost`, `prost-types` and `tonic-prost` are no longer dependencies; the processor's `tonic` transport and the connect-per-call logic are untouched.
- **Added (`rusty_tonic`):** feature `tonic-codec`, `rusty_tonic::tonic_codec::WireCodec<T, U>`: a `tonic` codec for `rusty_prost` messages, which was private to `rusty_a2a`. `rusty_a2a` now uses it, and `bytes` is no longer one of its dependencies. The feature is off by default, so the sans-IO core still pulls in nothing.
- **Changed (tooling):** `rusty_a2a/tests/golden/gen_vectors.py` becomes `rusty_prost/tools/gen_vectors.py`, taking `--proto`, `-I`, `--compile-all`, `--extra` (a consumer's hand-built cases), `--out` and `--label`. Proof the move changes nothing: run against `a2a.proto` it reproduces all 286 `rusty_a2a` vectors byte for byte (only the `generator` line of the file changed).
- **Tests (the vector test was written before the messages moved):** `tests/wire_vectors.rs` (7) checks the eight messages against 68 vectors made by Google's Python protobuf runtime from the vendored `ext_mcp.proto`: an empty and five random messages for each, plus hand-built cases (unknown fields, a scalar repeated, oneof members repeated and replaced, a `Pass` present but empty, an optional `bytes` present but empty versus absent, a header value that is not UTF-8, a code the schema does not know, a negative code). Each must decode and re-encode to the reference's bytes and again from those; every prefix of every vector and random bytes decode without a panic; bad UTF-8 and a length past the end are refused. `rusty_tonic/tests/tonic_codec.rs` (2) serves a `rusty_prost` message through a real `tonic` server and refuses a body that is not the message. The 120 existing guardrail tests and the pool tests pass with mechanical changes only (imports, `Value`, `encode_to_vec()` returning a `Result`; they drive a real gRPC client against a scripted server). 6 mutations of `wire.rs` (two swapped field numbers, a swapped oneof number, an optional field made plain, a moved tag, an extra field): all caught (one by the compiler), the extra-field one after a vector with an unknown field was added.
- **Known limitations:** `rusty_a2a`'s `server::push::tests::pinned_client_connects_to_the_validated_address_not_a_fresh_dns_lookup` needs DNS and fails in the sandbox, as it does on `main`. The upstream `ext_mcp.proto` is unchanged. The unit test that pinned `McpRequest`'s first bytes is gone; the vectors pin every field of every message instead.
