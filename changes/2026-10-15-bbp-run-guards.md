## 2026-10-15 - BBP run guards

- **Added:** `bbp pairs` manifest field `reads_per_turn` (every run's card must match it) and checks that each role used exactly one model per run, the same one in both arms, and that an extra N=2 role used a model the control also used; a violation refuses the evaluation, and so does an arm with no model evidence (a `result` line alone names no model) or a granted turn that observed none. The models come from the harness output, so this is observed, not declared; pinning the model is still done with `--model` in each role's launcher in the agents file.
- **Added:** `build.rs` records the build commit (`-dirty` or `unknown` when not clean) as `rusty_bbp_host::BUILD_SHA`; `bbp mod` prints it as `bbp_build_sha` and `bbp pairs` refuses unless it equals the checkout's HEAD, which must be clean and contain `min_commit`, and unless every saved run's own `bbp mod` output reports that same clean commit in `bbp_build_sha` (a missing, dirty, unknown, malformed, mismatched or mixed identity refuses). The output records both. The sha is recomputed on every build, so a binary built from edited code, an edited dependency or an untracked file reports `-dirty`, never a stale clean commit; every cargo build now runs one `git status`.
- **Added:** `bbp mod --max-usd C --criteria FILE` checks the dollar cost of every turn's harness output each poll and, over C, kills the harnesses and fails the run (a run that does not close is a failed run). It also fails closed when a model has no price, and a run that reaches `closed` or `cancelled` has its final usage checked against the cap before it counts as a success. It lags by a poll and by what a harness has printed, so it cuts a run short and does not bound spend exactly; the API key's spend limit remains the hard stop.
- **Tests:** a table-driven test for every decision row alone and for first-match-wins (each row against every later one; mutating the order of two rows fails three tests), the settings checks, the pin with the build commit, and the cap over, under and with an unpriced model.
- Host only: no engine, schema or log path.
- **Added (after review):** `bbp agents-check --control A --treatment B --criteria C` and the same check at the start of `bbp mod --criteria FILE --max-usd C`: every launched role pins a model (the `--model ID` or `--model=ID` argument of the launched program; argument boundaries are kept, so prompt text that mentions the flag pins nothing, and a `sh -c` line is parsed with shell quoting, only its `claude` commands count and each of them must pin, `#` comments are honoured, the only other commands allowed are `set`, `cd`, `rm` and `git` (what the shipped coder launcher uses; `git` only as `clone [-q] SRC DEST` or `rev-parse HEAD`, `set` only as `-e`/`-u`), with `exec` as the one wrapper, also inside `$( ... )` substitutions, assignments may not use names with a special meaning (`PATH`, `GIT_*`, `LD_*`), and anything else (`cp`, `mv`, `env`, a nested shell with or without a path, `eval`, control flow, a computed command, a backtick or nested substitution, an unreadable quote) is refused), every pinned model has a price, and the two arms pin the same model per role; the run refuses to start otherwise. The post-run check stays.
- **Changed:** cache writes are priced by lifetime: `cache_creation_5m` and `cache_creation_1h` in `docs/bbp/2b-criteria.json`. `bbp tokens` reads the API's `cache_creation` split if the harness prints it; whatever the split does not prove to be 5-minute is priced at the 1-hour rate, so cost is never understated. Not checked against a captured stream-json log.
- **Price file:** `claude-sonnet-5-5` `cache_read` corrected to 0.10 and the 5-minute and 1-hour write prices set from the owner's check against the price page; `prices_as_of` and `status` are left for the owner to update.
- **Fixed (independent review of #763):** `bbp tokens` prices each turn from the last `result` line's `modelUsage` (subagents included), cross-checks `total_cost_usd`, and treats a missing, incomplete, crashed or killed turn as unknown cost (criterion 7 inconclusive); writes are priced at the 1-hour rate and both cache TTL variables are pinned to `1h`; fast mode, priority tier and unpriced models are refused. Parsers are tested on real captured logs (`tests/fixtures/stream-json`); `modelUsage` carries no 5m/1h split.
- **Fixed:** the cap is checked after the final poll and a run over it fails; `decide` returns incomplete unless criteria 1 and 2 hold and every criterion a row names holds; criterion 1 needs replay equal to live in every run (`replay_equals_live` in the `bbp mod` output); the poll bound counts both arms' boundaries; boundary tests for the survivors of the review's mutations.
- **Fixed:** `bbp grade pack` writes `pack.json` (approved specs, two per task) and `unused.json` separately; the agents-file pin check parses shell launchers (see the pins commits above); `bbp pairs` requires each run's evidence marker and `cap_usd` in the manifest, and the build commit is recomputed on every build.
- **Fixed (second independent review):** a run the cap or `--max-wall-secs` stops still prints its `bbp mod` JSON with `stop` and `stop_reason` (exit non-zero), and `bbp pairs` loads it as a failed run. The cap fails closed on unreadable harness output and counts assistant messages after the last result. Only a task nothing has run on can start as an evidence run. Criterion 1 includes the null pairs' repeat runs. The Planning window counts its real boundaries. The decision table's code and note say the same, with the guard row for 1 or 2 not yet known to hold.
- **Changed:** an evidence run's launchers must be the program `claude` (or `sh -c` over it) with `--output-format stream-json`, no redirect or pipe, `--setting-sources ""`, and subagents disallowed; `--fallback-model`, `--agents` and `--settings` are refused; the moderator sets `CLAUDE_CODE_SUBAGENT_MODEL` to the role's pinned model. Captured against Claude Code 2.1.300: a project's settings `env` overrides the process environment, `--setting-sources` keeps it out, `CLAUDE_CODE_SUBAGENT_MODEL` is honoured and Opus 5.5 prices to the harness's total.
- **Changed (owner decisions, round three):** subagents are forbidden in the evidence run and Haiku stays unpriced; launchers pass `--setting-sources ""` (no settings source, not even the user's). Cache writes are priced from the main agent's `usage.cache_creation` split (valid because subagents are forbidden), with the 1-hour rate as the fallback, and `bbp tokens` logs the effective cache lifetime per turn and per run. A turn that ends with no valid result counts at its known lower bound toward the total and the per-run cap; its run counts as failed, so its pair leaves criterion 7's ratio and its cost is reported apart (`failed_pair_costs`, `total_usd_at_least`).
- **Changed (owner decision, grader):** `bbp grade pack` no longer writes `unused.json`; it holds the unused versions in `unused.held.json`. New `bbp grade release` seals the approved scores (complete, no unused id), records their sha256 in `release.json` and only then writes `unused.json`; `bbp grade join` takes `--unused-scores` and `--release` and refuses approved scores that changed after the release. The residual text-similarity limit of blinding is stated in the note.
- **Fixed (owner review comments on #763):** an evidence launcher must be exactly one harness session (two sessions in one log lost the earlier session's spend); a flag value the shell computes (`--tools "$t"`) is refused; a granted turn with no log at the end, and a log that exists but cannot be read, stop a capped run instead of being skipped; the moderator lock is taken before the evidence marker, so a refused startup leaves no marker.
