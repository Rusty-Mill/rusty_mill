## 2026-10-13 - BBP several live turns (Phase 2a)

- **Added:** `rusty_bbp` accepts `max_live_turns` (1 to the roster size) at `open`. Above 1 the state's roles fill the free turn slots in `turn_order`, each with its own token, deadline and `reads_per_turn` count; any transition revokes every live turn; `turn_granted` carries a `slice` of `messages` and `bytes` taken from the unreserved headroom, so concurrent turns cannot jointly overshoot the task totals. New code `bad_live_turns`. `TaskState::turns` replaces `turn` (`turn()` returns the first live turn); `Card::turns` replaces `Card::turn`; `Spent::reads_this_turn` moved to `Turn::reads`.
- **Changed:** `max_live_turns = 1` is the default and behaves as before: all 31 traces and the model tests pass unchanged. Log schema is 2 at one live turn and 3 above (written only then). A one-turn log is byte-identical to the earlier schema 2, checked against a golden produced by the pre-2a build, and a build that reads schema 2 alone refuses a schema 3 log.
- **Known limitations:** a verdict is not bound to the log revision the reviewer read (a concurrent finding does not void it), pinned by a test and listed as a known 2a gap in the spec; `rusty_bbp_host` still runs one harness at a time and opens tasks with `max_live_turns = 1`; its moderator needs one harness per live turn before the cap can be raised there. No contention or throughput measurement yet. Concurrent turns go only to roles that serve the same state; consultation and human `ask` turns share the same cap.
- **Fixed (review):** a write refused by a spent slice or `reads_per_turn` ends its turn and regrants it before the error returns, and the replacement charges `turns`; the budgets were not evaluated on that path, so refused writes could mint turns past the limit without escalation. They are now evaluated after a rejection too (also at one live turn).
- **Known limitations (added):** with several finalizers live, the first `verdict` revokes the others, so a second finalizer's veto is not guaranteed.
