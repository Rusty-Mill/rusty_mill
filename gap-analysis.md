# Gap analysis — rusty_-rusqlite vs. `rusqlite` 0.40.2

Generated by the parity-loop process. Target crate (`rusty_rusqlite`) had
zero code at generation time, so every row below is a gap by construction —
this is a candidate list produced from the reference surface, not yet
independently verified row-by-row for platform applicability once the
engine exists to check against.

**Reference pinned at:** `rusqlite` 0.40.2 (docs.rs, fetched 2026-08-14).
**Scope decision (user, this round):** pure-Rust reimplementation, no
`libsqlite3-sys`/C dependency. Full backlog generated now rather than
bootstrap-first (see README/ARCHITECTURE for the resulting non-goals).

**RustyMill sibling check:** `rusty_db` ("Database abstraction layer,
SQLAlchemy-like" — an ORM-style layer, not a SQL engine, so unlikely to
contain a reusable parser/B-tree/VM) was the only namespace repo plausibly
relevant to Part A. The actual grep-level check is **unresolved** — this
session's repo-scope is locked to the `baileyrd` owner tier and can't
attach a `Rusty-Mill/*` repo for read+scan in the same session (cross-owner
attach was rejected). Re-run `scan_rustymill_repos.sh` against `rusty_db`
in a session scoped to that repo before assuming Part A is genuinely
greenfield. No other sibling repo's stated purpose overlaps a SQL engine or
this specific API-compat layer, so Part B rows are marked "none found"
with lower confidence than a full scan would give.

## Part A — Foundation tier

Not derived from rusqlite's public API (rusqlite doesn't expose these —
they're internal to real SQLite). Required before most of Part B is
implementable at all: you cannot honestly implement `Connection::execute`
without something underneath that can execute SQL. Source = `spec` (SQLite
file format + query language documentation), not a diff.

Ordered by dependency — each row generally needs the ones above it.

| # | Component | Category | Source | Reference | Est. size | Notes |
| - | --- | --- | --- | --- | --- | --- |
| A1 | Value/type model (`Null`/`Integer`/`Real`/`Text`/`Blob`) | type | spec | SQLite "Datatypes in SQLite" doc | S | Foundation for everything else; mirrors rusqlite's `types::Value` shape so the API layer can adopt it directly (see B-Types row) |
| A2 | SQL tokenizer | fn/type | spec | SQLite "Query Language Understood by SQLite" grammar | M | Lexes a SQL statement into tokens; no engine semantics yet |
| A3 | SQL parser (DDL subset: `CREATE TABLE`) | fn/type | spec | SQLite `CREATE TABLE` syntax diagram | M | Smallest DDL slice needed before any DML has somewhere to write to |
| A4 | SQL parser (DML subset: `INSERT`/`SELECT` w/o joins) | fn/type | spec | SQLite `INSERT`/`SELECT` syntax diagrams | L | Split into `INSERT` (S) and single-table `SELECT` (M) as separate issues when filed |
| A5 | In-memory page/record storage backend | fn/type | spec | SQLite file format doc (page/record layout, informing the in-memory analog) | L | Deliberately in-memory-first (see ARCHITECTURE non-goals); on-disk file format is a later gap, not this round |

| A8 | `Connection`/`Statement` skeleton wired to A2–A7 | type | spec | this repo's `src/connection.rs` (already has `open_in_memory`/`close`) | M | Where `execute`/`query_row` first become real instead of stubs |

## Part B — `rusqlite` API-surface tier

Source = `diff` (docs.rs public-item listing vs. this crate's current empty
surface). Grouped by type/module with cohesive method-groups as gap rows,
per the skill's issue-sizing rule — filing one issue per individual method
here (~300 methods total) would be far too fine-grained; one issue per
unrelated 10-method type would be far too coarse.

All rows below depend on Part A existing in some working form first —
these are literally not implementable before A8. None are `Breaking?`
(pure additions against an empty crate) and none had a RustyMill sibling
match (`rusty_db`'s ORM-layer purpose doesn't overlap rusqlite's low-level
API shape).

  candidates** (conflict with the no-C-dependency decision), not silently

  someone later wants C-extension loading support despite the sovereignty
