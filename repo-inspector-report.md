## Tool notes (repo-inspector's own behavior on this run)

- **A real bug in `index_workspace_capabilities.sh` was found and fixed
  during this run**, not before it: the script walked a crate's entire
  directory tree with no boundary at another workspace member nested
  inside it (`crates/rusty_term/l13`, `crates/rusty_json/rusty_json-derive`,
  `crates/rusty_tokio/rusty_tokio-macros`, `crates/rusty_err/derive`), so a
  nested crate's public items got double-tagged as if they also existed in
  the parent crate — 19 spurious index rows and 10 phantom clusters. Fixed
  in `repo-inspector` v1.0.1
  ([baileyrd/skill_pack#89](https://github.com/baileyrd/skill_pack/pull/89),
  merged) before this report was generated; all numbers above are from the
  fixed script.
- **`repo-config` had not been applied to this workspace's root** before
  this run (score 1/11 — the standard set exists per-crate for 49 of the
  ~90 merged crates, but not at the root). Per `repo-inspector`'s own step
  0, that's a hard prerequisite; applied in
  [Rusty-Mill/rusty_mill#69](https://github.com/Rusty-Mill/rusty_mill/pull/69)
  (open, not merged — a separate decision from this report) before the
  scan ran.
- This pass covers the highest-signal subset of both a 507-cluster and a
  76-dependency surface, not either exhaustively — see the method notes at
  the top of each section for what was in scope. A `FOCUS`-narrowed re-run
  on a specific capability area, or simply more review time, would surface
  more.
