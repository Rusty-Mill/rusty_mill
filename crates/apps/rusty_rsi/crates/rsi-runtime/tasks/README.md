# rusty_rsi toy task suite

There is one task per AIDE² family. All data is generated by
`generate.py`, which is deterministic: rerunning it reproduces every file
byte for byte.

| Task | Family | Metric | Naive baseline (public) |
|---|---|---|---|
| `ml-regression` | ML-lite | `r2`: R² clamped to [0, 1] | predicts the training mean: ≈ 0 |
| `tsp-heuristic` | heuristic optimisation | `tour_ratio`: mean of min(1, reference ÷ tour length) | identity order: ≈ 0.2 |
| `scaffold-oracle` | harness engineering | `accuracy` | one oracle call per question: 0.8 |

## Solution contract

A solution is one Python file, standard library only. It runs as:

```text
python3 solution.py data/<inputs> output.txt
```

The working directory is fresh. It holds `solution.py` and a `data/`
directory, which contains the task's `shared` files plus one split's inputs.
The run has the following environment:
- **Seed:** `RSI_SEED` holds the run's seed.
- **Network:** none.
- **Filesystem:** read access to system directories only.
- **Limits:** the CPU, wall-clock and memory limits from `task.json`.

Write one answer per input line to `output.txt`.

## Layout

```text
<task>/task.json      id, family, metric, shared, inputs, floor, limits
<task>/public/        shared files, inputs, labels.txt, baseline.py (x0)
<task>/private/       held-out inputs and labels.txt; never readable by a solution
```

## Known limitations

- **Readable oracle.** `scaffold-oracle`'s oracle is a deterministic
  simulator, and its source is staged with the solution. A solution can
  therefore read or reimplement it, or simply compute the arithmetic
  itself. A real model-backed harness task needs the P3 broker.
- **Small TSP reference.** `tsp-heuristic`'s reference length comes from
  nearest neighbour plus 2-opt, so strong solutions hit the cap of 1.0.
