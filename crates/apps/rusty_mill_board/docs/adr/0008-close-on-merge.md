# ADR-0008: Close a card when its pull request says so

- **Status:** Accepted (2026-11-23): Nano concurred ("Concur", comment on Mill Board card #1620, 2026-11-23, with the design artifact linked on the card) with option (c), marker-only. Turning `auto_close` on in a deployment is a separate owner decision, still pending. Built in three PRs: the read-only merge watch (#1842), the marker close (this change), then `card_unclose`.

## Context
Work that merged kept sitting open on the board, so finished decisions were re-made (#1620: #762, #1078, #1563). Closing relied on an agent remembering. The sync's old rule was that moving a card to Done needs review: the `github-sync` actor holds no capabilities and never moves a card.

## Decision
- The **merge watch** (`mergewatch`, run by the GitHub sync thread, at most every 5 minutes) reads recently merged pull requests of the registered GitHub repositories and lists the open cards they point at in `board_metrics.merged_open`. The board core stays pure: all I/O is behind the `MergedPulls` port.
- Only one link may close a card: a standalone prose line `Closes card #N` (also Fixes/Resolves) in a merged PR's body, from a repository of the card's own project. The word `card` is required, because a bare `Closes #N` makes GitHub close issue N. Quotes, code, comments and longer sentences never count. Evidence, `card #N` mentions and earlier PRs of a multi-PR card are listed, never acted on.
- Closing is **off by default** (`auto_close` in the GitHub settings file). Without it the watch only lists, and the `marker` entries are the dry-run report of what it would close.
- The actor is `merge-watch`, holding `Record` only; the board refuses that name (and `github-sync`) from any caller. The close is **wider than `Record` is elsewhere**: `Card::closed_by_merge` closes from Backlog, Ready or any work column without taking the transition table, so it stands in for the review step. It adds the PR as evidence, moves the card to Done as shipped work (`done_ms` set), releases the claim **even a live one held by someone else** (the comment names the column it was in), and logs the move as that actor's. It refuses a Blocked, Parked or gated card (a gate lies between it and Done) and a Done card. The watch also skips parents: their children decide.
- Every merged PR is listed (mentions and evidence too), whatever its branch or author. Only a marker may close, and only if the PR merged into the repository's default branch, its author is an owner, member or collaborator, and nothing touched it after the merge (`updated_at` within a minute of `merged_at`). The body is read as it is now and the REST API gives no edit history, so this is evidence, not authentication: it cannot tell who wrote the text, and any later activity (a comment, a label) also withholds the close, which leaves the card listed for a person. An immutable merge-time record would need GraphQL edit history or a stored snapshot; until the owner accepts this trust model, `auto_close` stays off.
- The marker must be literal: a line that needed code or comment stripping, or has anything beside the directive, is a mention. The write is fenced: it commits once at the scanned revision, as an actor limited to the card's project, after rechecking the repository and that the card is no parent; a changed card is never retried, it stays listed. The childlessness check and the commit hold one gate (`Board::links`) that every parent-link writer (`card_add` with a parent, `card_plan` with a parent) also holds, so a link cannot land between them. The gate is per board process: a second board writing to the same store is not covered. That is not enforced in code: `auto_close` is a setting an admin can turn on, so the owner decides whether to accept it before any deployment enables it. The write takes its workflow snapshot once and reads the cards from it (`cards_in`), so it never takes the workflow lock twice while holding the gate.
- ADR-0006 is unchanged: the watch reads the forge directly and never decides from external refs.

## Consequences
- A merged PR whose author wrote the marker ends its card without anyone remembering; a wrong marker closes the wrong card, which `card_unclose` (next PR) reverts.
- The sync's "moving to Done needs review" rule now has this one exception, for a marker in a merged PR.
- A card the marker cannot close stays listed in `merged_open` for a person.
