# BBP v0.3 review (integrated lens)

## A. Verdict

**BUILD WITH CHANGES.** The architecture (one transactional authority, token-fenced turns, revision- and run-bound approvals) is sound and v0.3's move to a normative table was right. But the table still has sequences that misfire: a late report from an abandoned run resets a reviewed task, the yield guard forbids every useful yield, an `error` run has no exit, and resume can skip the Tester.

## B. Did v0.3 fix v0.2?

Mostly. Run binding closes the stale-evidence gap but defines "current run" by storage order, so a zombie run can re-open a judged candidate (F1). Cutting attempt generations leaves the fence weaker than claimed: with one process per role the adapter will attach the *next* turn's token to a stale in-flight call (F5). The guarded yield return is fine, but the yield *entry* guard ("target has a turn in this state") is unsatisfiable under the one-role-per-state default schedule, so yield is dead (F2). Token-fenced reads and `turns` are sound; `read` charging is unspecified (F11). T19 as an "entry row" violates the design's own checker property that no two rows match one event (F8).

## C. Findings

**F1** · blocking · Run and test report; T13; R16
- issue: "Current run = latest run with a stored report" plus T13 means any report, from any started run, resets `review`/`merge_gate` to `test`. Nothing marks a timed-out run abandoned, and the table has no trigger that legitimately starts a new run outside T8/T19, so T13's only realistic trigger is a zombie.
- failure scenario: run_02 supervisor hangs; moderator times out and starts run_03; run_03 passes; Tester and Reviewer approve; task sits in `merge_gate`. run_02's supervisor wakes and stores its report. R16 accepts (run was started). T13 fires: verdicts staled, back to `test`, "current run" is now run_02. Approved work is undone by a crash artifact.
- fix: moderator records `run_abandoned(run)` on timeout; R16 rejects reports for abandoned or non-latest-started runs (`stale_run`). Define current run as the latest *started* run. Then T13 only fires on an explicit human `rerun` channel action (add it) or delete T13.

**F2** · blocking · T21; Default schedule; Risks ("yield_to covers ask/answer")
- issue: T21's guard "target role has a turn in this state" is never true for the realistic case: in `build` only Coder has a turn, in `test` only Tester. Coder cannot yield to Tester to clarify an acceptance criterion; Tester cannot yield to Coder. Yield is dead on paper.
- failure scenario: Coder in `build` posts `ask` to Tester with `yield_to: tester`; rejected (`wrong_state` or similar); Coder either guesses or burns a `request_decision` to the human for a question a peer could answer.
- fix: replace the guard with "target is assigned, is not Reviewer, and the state is `planning`, `build`, `test` or `review`". Keep "no yield already open" and clear the return-to record in T23.

**F3** · blocking · T9; R3; Commentary "Recovery"
- issue: A `status: error` report (two runner failures) grants the Tester (T9), who can neither `approve` (not passed) nor honestly `revise` (needs a blocking item against the candidate). No row restarts a run while a current run exists.
- failure scenario: sandbox image breaks; run_01 and run_02 crash; `error` stored; Tester granted; Tester posts `revise` with a fabricated blocking item to make progress; `iteration += 1`; Coder is blamed for infrastructure; repeat until `iterations` exhausted → `escalated`.
- fix: add a row above T9: `test`, `test_report_stored` with `status: error` → `escalated(from: test)`. In T19, entering `test` starts a new run when the current run is `error`.

**F4** · blocking · T18; R17
- issue: resume targets include `review` with no guard that a Tester `approve` exists for the current candidate and run. R17 at `merge_gate` only checks the Reviewer. Resume into `planning` does not apply T2's clears.
- failure scenario: task escalates from `test` on `reads` exhaustion; human extends and resumes to `review` by mistake; Reviewer approves; human approves at `merge_gate`; candidate merges with no Tester verdict ever recorded, violating Goal 3.
- fix: T18 guard: `review` requires a Tester `approve` on the current candidate and current run; `planning` applies T2's effect. Otherwise only `from`, `build`, `test`.

**F5** · non-blocking (would be blocking if the fence is the only control) · Host requirements "Token injection"; R14; Commentary "Only one turn is live"
- issue: "Never substitutes a newer token for an older process" is vacuous when there is exactly one process per role; the same process receives the next grant. A model call still running past the deadline will have its tool calls stamped with the new token.
- failure scenario: Tester's inference runs long; deadline passes; T24 regrants Tester (default schedule); the stale inference's `pass` arrives with the fresh token and ends the new turn immediately. Two turns charged for nothing.
- fix: host requirement: the adapter must cancel in-flight generation and drop queued tool calls on `turn_ended` before honouring a new grant; `turn_granted` carries a turn id the adapter must echo and the store checks equals the live turn.

**F6** · blocking (for implementation) · R5; Message kinds table
- issue: R5 rejects with `wrong_state` but no table defines which message kinds each state accepts. The artifact gating table exists; the message one does not. "Make illegal states unrepresentable" has no data to implement from.
- failure scenario: implementers disagree whether `propose` is legal in `plan_gate`; the model checker cannot be written.
- fix: add a `States` column to the message-kinds table, or state the rule: "any kind the role may post, in any state where that role holds a turn; `verdict` only in `test` (Tester) and `review` (Reviewer); `request_decision(gate)` only in `planning`."

**F7** · non-blocking · Event `task_opened`; Planner role
- issue: `task_opened` carries repo, profiles and budget but no task statement. The Planner has nothing to plan from except an unaddressed human `ask`.
- failure scenario: Planner is granted, finds no task, posts `ask` to human, wastes a turn.
- fix: add a `brief` artifact kind (writer: human at `task_opened`) and require T5's spec to `refs` it.

**F8** · non-blocking · T19 and T6, T10, T11, T13, T15, T17; Test strategy
- issue: T19 is an entry action phrased as a row and duplicates grants already in other rows, contradicting "no two rows match the same event".
- fix: move T19 to a footnote "entry actions", delete the per-row grants, keep the run-start condition.

**F9** · non-blocking · Default schedule (gate states); T24
- issue: In `plan_gate`/`merge_gate`/`approved` a turn is granted "to answer a human ask". If the agent cannot answer and the deadline passes, T24 regrants per default schedule, i.e. again, charging `turns` each time until T3.
- fix: a human `ask` grants exactly one turn; after it ends the state returns to waiting.

**F10** · non-blocking · R9; `request_decision`; T4
- issue: a non-gate `request_decision` need not address `human`, yet only the human can settle it; its deadline then escalates the task.
- fix: R2/R9: `request_decision` requires `human` in `to`. Also say who sets its deadline (the store, host default).

**F11** · non-blocking · R11; Reads
- issue: "once per artifact id per turn" covers `get_artifact`; `read` charging is unspecified and a lost `read` response retried is double-charged.
- fix: "`read` charges one per call; a retried `read` with identical `(after, limit)` in the same turn is free."

**F12** · non-blocking · Evaluation order
- issue: step 2 (terminal check) precedes step 3 (`op` lookup) but exempts replays, which cannot be identified before the lookup.
- fix: swap steps 2 and 3.

**F13** · non-blocking · R17 `spec_mismatch`; R16
- issue: candidate/spec equality is checked at human approval, long after the Coder could have learned it.
- fix: check at `put_artifact(candidate)` in R16; drop the `spec` field from the manifest and have the store stamp the approved spec.

**F14** · non-blocking · Capability matrix (Reviewer); T20
- issue: Reviewer reads only human messages addressed to `reviewer`. A human `decision` settling the Reviewer's request need not carry that `to`, so the Reviewer is regranted (T20) blind.
- fix: Reviewer may also read any `decision` whose `subject` is its own message.

**F15** · non-blocking · Runner API; R16
- issue: any runner principal can write a `passed` report for any started run. The run id is not a credential.
- fix: `run_started` mints a per-run runner secret the supervisor must present; R16 checks it.

**F16** · non-blocking · T3 vs effects of T11/T15/T17
- issue: budget overrun is caused by another row's effect; ordering of cascaded triggers is undefined.
- fix: "budget checks run after a row's effects as a separate event".

## D. Open questions

- **Q1.** No opinion on absolute values; set `reads_per_turn` ≥ 4 + max diffs so a fresh Reviewer can read spec, candidate, report and every diff in one turn.
- **Q2.** No. Skipping `test` reintroduces unevidenced verdicts (Goal 3) and the guard ("only flagged files") is not checkable from store data.
- **Q3.** No. `ask`/`answer` already covers inline human answers; a second human-wait mechanism doubles the state space.
- **Q4.** Defer; cut Appendix B from the spec until v0.3 is measured.

## E. Missing pieces

- How the Coder sees the code. The store holds diffs against `base`, but no host requirement gives the Coder a read-only checkout at `base`. Without it the protocol is untestable with a real task.
- Task brief (F7).
- Diff apply failure: distinguish `failed` (tests) from `error` (patch does not apply, dependency missing) and route the latter to the Coder, not escalation.
- Flaky tests: a human-triggered `rerun` (see F1) is the minimum.
- Run abandonment (F1); time source for deadlines.
- Test authorship: Tester can post no artifacts, so a missing test case always costs a full `revise` iteration. Acceptable, but say so.

## F. What to cut

- T13 as a general row (F1); replace with explicit `rerun`.
- T19 as a row (F8).
- Manifest `spec` field (F13).
- Task-level `reads` budget: `reads_per_turn × turns` already bounds it.
- `usage`/`advisory.tokens`: unverifiable; move to measurement notes.
- Appendix B.
- `propose`: overlaps `finding` + `request_decision`; keep only if the proving run uses it.

## G. Top three changes

1. Fix run identity: `run_abandoned`, reject non-current-run reports, redefine current run (F1), and add the `error` exit (F3).
2. Make yield usable: rewrite T21's guard (F2), and add the message-kind-by-state table so R5 is implementable (F6).
3. Guard T18 against skipping the Tester and apply T2's clears on resume to `planning` (F4).

## H. Confidence

Medium-high on the table analysis (F1–F4, F6, F8); these follow from the text alone. Medium on F5: it depends on how a real adapter and inference runtime behave, which the document cannot settle. I could not assess the claims about MCP, A2A, AG-UI or Delta, nor whether the budget defaults are realistic; verify the MCP claim against the resources spec linked in the Summary, and treat the Delta appendix as aspirational. The v0.2 reviews were not available, so I could not confirm every traced sequence is covered.
