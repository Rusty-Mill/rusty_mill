# BBP v0.2: Merged Round-Three Review (Claude, ChatGPT, Gemini)

Three fresh-session reviews of v0.2 (`review/v0.2-review-*.md`). All three: BUILD WITH CHANGES. All three say the v0.1 problems are fixed and that what remains is event-sequence gaps in the state machine, not architecture. ChatGPT's framing is the right one for v0.3: write the transition table as an executable model with guards and precedence before any agent connects.

## 1. Raised by all three

| Topic | Claude | ChatGPT | Gemini | Fix for v0.3 |
| --- | --- | --- | --- | --- |
| A later report replaces the evidence behind an approval; report content unvalidated | F1 | F1 | F4 | Each run has an id and frozen profile. Verdicts and merge approval name the run, not "the current report". A new run for the current candidate stales verdicts and returns `review`/`merge_gate` to `test`. R17 requires that run `passed`. Store rejects a report whose `status` disagrees with `exit_code` and failure counts. |
| `changes_spec` after plan approval is a dead end | F2 | F2 | F cut | Cut `changes_spec`. A human who wants a spec change uses `human_rejection → planning`; the approved spec is cleared so old candidates fail `spec_mismatch`. One path, not two. |
| Yield, deadlines and attempts interact badly | F7 | F3 | F2 | Yield ends the yielder's turn. Return is a fresh `turn_granted` only if state and candidate are unchanged and no human wait intervened; otherwise the new state's schedule applies. Yields allowed only to roles with a turn in the current state. See attempts below. |
| Continuation after human waits and escalation is incomplete | F4, F9 | F4 | F3 | `escalated` records `from`; `resumed` may target it, never a terminal state. Settling a `request_decision` cancels its deadline and regrants the requester's turn. Entering `test` with a current run grants the Tester. `approved → build` on base drift clears candidate approvals, keeps the spec. |
| Read budget loops and unfenced reads | F8 | F5 | F5 | Charged reads require the live token and charge that turn. One read per artifact id per turn. Add a task-level `reads` total and a `turns` total; exceeding either escalates. |

## 2. Raised by two

| Topic | Who | Fix |
| --- | --- | --- |
| `op` replay must precede token and state checks | Claude F3, ChatGPT F8 | Rule order: authenticate principal and task, look up accepted `op`, compare payload, return the original result. Only then R14, R18 and the rest. Tests cover retry after turn end, state change, cancel and close. |
| Manifest `repo` unchecked | Claude F5, ChatGPT F7 | Drop `repo` from the manifest; the task owns it. Freeze the run profile by digest. Name the tree-hash algorithm. |

| Cut attempts | Claude F (cut), Gemini F2 (symptom) | Tokens already fence stale writes. Attempt generation adds a second clock with no remaining job. Cut it; a deadline just ends the turn. |

## 3. Raised by one, accepted

- **R14 wording exempts agents only** (Gemini F1). Say "every Agent API mutation"; runner and human principals authenticate through their own channels.
- **Reviewer cannot read the human's answer** (Claude F6). Reviewer reads messages from `human` addressed to it.
- **`revise` with empty `blocking`; `escalate` as a verdict value** (Claude F12). `revise` requires one blocking item. Cut `escalate`; `request_decision` covers it.
- **Gate trigger is too loose** (Claude F10). `request_decision` carries `gate: "plan"`; gate requests carry no deadline.
- **Planner and Reviewer stubs in the proving run** (ChatGPT F9). The gates cannot be tested without them. Stubs go through the normal APIs.
- **Artifact size pre-flight** (Gemini E3). `max_artifact_bytes` checked at the envelope before any store work.
- **`abort_turn` from the host** (Gemini E2). Host-side only, ends the turn with cause `aborted`.
- **Budget rejection changes turn or escalation state** (ChatGPT E). Fix the property statement.

## 4. Disagreements

- **`log` kind.** Gemini: fold into `test_report`. Recommendation: keep. The Reviewer reads reports and not logs, so the kinds carry a real access-control difference.
- **Appendix A.** Gemini: cut. ChatGPT: keep as hypothesis. Recommendation: keep, one paragraph.
- **Rule and record counts.** ChatGPT: stop optimizing for a number. Agreed; v0.3 drops the "eighteen rules, five records" line.

## 5. Settled answers to Q1–Q5

- Q1: a fixed set of required profiles, frozen by digest; all must pass. Start with one.
- Q2: no waivers in v0.3. A failed run cannot reach `merge_gate`.
- Q3: configurable; define what counts first. Gemini's starting values: messages 40, bytes 5 MB, reads per turn 30, task reads 150, iterations 4; plus `turns`.
- Q4: fresh Reviewer session per candidate. Unanimous.
- Q5: deferred. Unanimous.

## 6. Decisions for Nano before v0.3

1. Cut attempt generations (tokens and deadlines suffice).
2. Cut `changes_spec` (rejection to `planning` is the one path).
3. Cut the `escalate` verdict value (`request_decision` covers it).

All three are recommended cuts. Everything else above is consensus and goes in without a question.
