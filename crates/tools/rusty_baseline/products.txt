# The products rusty_baseline measures: each app's shipped binaries.
#
#   <package>[:<features>] <bin> <exit|idle> [@platform=<os>|@unsupported=<os>] [@expect-exit=<code>|<os>:<code>] [KEY=value...] [args...]
#
# `@platform=linux`, `@platform=windows`, or `@platform=macos` immediately
# after the mode restricts a product to that OS. With no declaration a product
# remains unrestricted.
# `@unsupported=<os>` instead excludes only that OS. This preserves eligibility
# on every other host when a product has one narrow, temporary platform gap.
#
# `exit`: a cheap command that runs to completion; startup is its wall time.
# Every warm-up and timed invocation must exit 0 unless `@expect-exit` declares
# an exact code. An OS prefix changes the expectation only on that OS; other
# hosts still expect 0. The declaration follows the optional platform policy.
# Unexpected exits (including signals) fail the run, not a valid startup sample.
# `idle`: a server or daemon, started with no real config (dummy secrets,
# data in the scratch home), sampled once settled, then killed.
#
# Not measured: Tauri desktop apps (inventory-tauri, sessionmgr-desktop,
# the nexus and rusty_key shells: they need system WebKit); mill-term and
# nexus-tui (need a real tty); rusty_voice (needs a display); rusty-keys
# and rp-server (need a model or config file to start); dev and test
# helpers (xtask, harnesses, examples).
