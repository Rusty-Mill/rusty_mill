## 3. Top recommendations

**R1 — Adopt `rmcp` (MIT) as the `mcp` crate's foundation; rewrite PRD 07's transports as adapters over it.** *What:* PRD 07 today hand-specifies `StdioMcpClient`/`SseMcpClient` with raw JSON-RPC framing, `initialize`/`tools/list` sequencing, heartbeat/reconnect — all of which `rmcp` 1.7 already provides (stdio + streamable HTTP, the protocol state machine, a `#[tool]` macro). *Why:* re-implementing the MCP wire protocol is exactly the kind of undifferentiated work the harness should not own; `rmcp` is the *official* SDK, tokio-native (fits ADR-0003), and tracks the spec. Our value-add (`mcp__server__tool` namespacing, `McpPolicy` vetting, `ApprovalGate` first-use, the `McpToolFn`→`ToolFn` adapter) sits *above* `rmcp` unchanged. *Target:* a **new ADR** ("`mcp` crate builds on `rmcp`") + revise **`docs/prd/07-mcp.md`** so `McpClient` is a thin trait over `rmcp`'s client and the server role wraps `rmcp`'s server. *Rust + AI-first:* keeps us in-ecosystem, no foreign stack. *License:* **`rmcp` = MIT (verified, dependency-safe); opendocswork-mcp = GPL-3.0 (reference-only, never vendored).** Confirm `rmcp`'s exact dep tree against `cargo deny` (coding-standards §8) before pinning. *(proposal/v1 intent.)*

**R2 — Standardize the observe hook on a fixed lifecycle-event enum (Eino's callback-aspect pattern).** *What:* Eino injects cross-cutting concerns (trace/metrics/logging) at five fixed points (OnStart/OnEnd/OnError + stream variants). Our kernel already exposes `on_event` to the `Tracer` (PRD 04), but the *set* of events is implicit. Pin it as a small closed enum — e.g. `KernelEvent::{TurnStart, ToolStart, ToolEnd(ToolOutcome), TurnEnd, Error(KernelError)}` — so `Tracer`, structured logging (`RUSTYKEYS_TRACE`), and the future OpenTelemetry seam (BACKLOG) all consume *one* typed stream instead of bespoke call sites. *Why:* makes the observability surface exhaustive-match-checked (same discipline as our `FailureType`/`ToolStatus`), and the closed enum is the natural extension point when OTel lands. *Target:* a short **ADR** (observe event taxonomy) referenced from **`docs/prd/04-observe.md`** §Tracer; the OTel mapping note goes in BACKLOG. *Rust + AI-first:* trait-object hook + enum is idiomatic; no Go `Handler`-builder machinery. *License:* n/a (pattern). *(proposal/v1 intent.)*

**R3 — Add a validation-gated promotion rule to skill grooming/consolidation (SkillOpt pattern).** *What:* SkillOpt promotes an edited skill only when a validation pass confirms it does not regress. Our skill grooming (PRD 03 `refine`/`merge`/`split`, which call `Store::remove()`) and consolidation have **no regression gate** — a bad merge can silently degrade recall. Add the *rule* to testing-strategy: groomed/superseding skill writes are gated behind **golden-episode replay** (the deterministic verdict-reproducibility harness already in testing-strategy §3) — if replay regresses, the supersede is rejected/flagged, not committed. *Why:* directly serves "verification you can trust" — the self-improvement loop (PRD 03) currently can *un*-learn with no guardrail. *Target:* **`docs/dev/testing-strategy.md`** (the gate as an engineering pattern) with a cross-ref to **`eval-plan.md`** (AI-engineer owns the *scoring* that drives the gate). *Rust + AI-first:* reuses `FakeLanguageModel` + golden replay; no new infra. *License:* n/a (pattern). *(proposal/v1 intent — keep the *mechanism* a v2 seam; v1 just states the gate exists and is enforced at `sleep`/`/groom`.)*

**R4 — Assess but defer a typed-graph `compose` API for the multi-agent seam; ship `SessionFactory` for v1.** *What:* Eino's typed-node-I/O graph (`compose`) and ADHD's fan-out/critic both point at a richer multi-agent orchestration API than our single `SessionFactory::spawn_child` (ADR-0017). *Verdict: over-engineering for v1.* `SessionFactory` + the `agent` tool covers single-level subagent spawning, which is the only v1 need; a typed-graph DSL would add a large surface (node typing, edge wiring, interrupt/resume state) the kernel-as-thin-loop thesis doesn't want yet. *Why defer:* Eino's own graph value (interrupt/resume, typed I/O between nodes) maps to features we already cover differently (approval-gate/plan-mode for interrupt; `ChildSession` boundary for I/O). Record the *intent* so it isn't lost. *Target:* **BACKLOG** "Multi-agent orchestration" item — annotate with "Eino typed-graph `compose` + ADHD divergent/critic are the reference patterns when this graduates from `SessionFactory`." *Rust + AI-first:* if it ever lands, a Rust typed-graph (builder + `enum` node kinds) — not a YAML DSL (rejects AI-Q's config-graph). *License:* n/a. *(speculative / explicitly deferred.)*

My R3 gate and their eval-plan must agree on what "regression" means over the shared golden-episode fixture (the Round-1 split: testing-strategy = deterministic substrate, eval-plan = model maturity).

- **Systems architect:** R1's `rmcp` dependency adds to the crate DAG (`mcp` gains an external dep) and the `cargo deny` license/ban policy (coding-standards §8) — they own the supply-chain sign-off. - **Product/roadmap persona:** sequencing R1 (`rmcp`) into Phase 12 (MCP) and R3's gate into Phase 3/4 (memory) is their call; R4 stays in the post-phase backlog.
