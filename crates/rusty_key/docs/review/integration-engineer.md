# Integration Engineer Review — Rusty Keys

## 1. Scope & lens

Every boundary where Rusty Keys meets an external system: the aisdk provider edge, the MCP client+server, the axum web gateway (incl. SSE), the Tauri IPC contract, secret/credential flow, web-tool egress, and cross-boundary test strategy. I judge what must be pinned **now** (cross-cutting, cheap to specify, expensive to retrofit) vs **deferred** to the phase that actually builds the surface (12/14/15). I agree with the Plan that full OpenAPI/IPC-schema files are gold-plating pre-code; the tables in PRDs 06/07/08 are the contract. The gaps below are about *semantics that no table captures*, not file format.

## 2. Validated gaps (from the focus list)

- **aisdk integration is almost entirely unspecified at the boundary.** `01-kernel.md:103` says "`Session` handles retry or surfaces to caller" — that is the *entire* retry/backoff/rate-limit/timeout policy. No version pin, no `429`/`Retry-After` handling, no per-call timeout, no provider-quirk normalization notes. This is the single highest-leverage gap and it is cross-cutting (kernel, consolidation, judge, embed, summarisation all call aisdk). PIN NOW.
- **Secret redaction is a future seam, but the leak surface is live now.** `ToolEvent.args` is the raw `serde_json::Value` (`04-observe.md:33`), recorded verbatim by the Tracer, written to `evidence.jsonl` (`06-app.md:69`), served over `GET /evidence` (`06-app.md:248`) and pushed via `rk://tool_event` / `session_evidence_recent`. MCP SSE auth tokens, `web_*` keys, and any secret an agent passes as a tool arg flow straight into an append-only on-disk journal and across the IPC/HTTP boundary. `RedactPolicy` is listed only as a seam (`02-constrain.md:265`). A redaction *rule* (not the policy machinery) must be pinned NOW because the journal format is being designed now and is append-only.
- **SSE `/stream` framing is undefined.** `06-app.md:246` lists `GET /stream` as "SSE stream of token chunks (`rk://token` events)" — but no event `name:` set, no framing for tool_event/turn_complete/approval over the same stream, no completion/error sentinel, no relation to `POST /chat` (does `/chat` block while `/stream` streams the same turn? how does a client correlate?). The Tauri side has 8 typed events; the gateway collapses them to "token chunks." DEFER detail to Phase 14, but the *protocol shape* (one SSE channel mirroring all 8 `rk://` events, with `id`/`event`/terminal sentinel) should be sketched NOW so the frontend's web-adapter seam (`08-frontend.md:360`) is real.
- **Web-tool egress is not bound to NetworkExfilCheck.** `NetworkExfilCheck` only inspects `bash` args (`02-constrain.md:65,130`). `web_fetch`/`web_search` (`03-feed.md:98-114`) take an arbitrary URL with no allow/deny-list, no SSRF guard (localhost/`169.254.169.254`/RFC1918), no max-redirect/size enforcement beyond the 50k char cap, and no policy hook — they are gated only by the boolean `RUSTYKEYS_ALLOW_WEB`. An agent with web enabled can fetch cloud metadata or internal services. PIN NOW (egress rule); the policy plumbing can follow.
- **Multi-session gateway has no lifecycle/eviction.** `06-app.md:260` routes `session_id` to a `HashMap<String, Session>` with no TTL, no idle eviction, no max-session cap, no auth-to-session binding. Each `Session` holds a kernel, SQLite handles, and history — unbounded growth and a cross-tenant `session_id`-guessing risk. DEFER to Phase 14, but note the eviction contract now.
- **MCP SSE auth/transport detail is thin.** `auth_token_env` is specified (`07-mcp.md:85`) but there is no statement of *how* the token is sent (header? which?), no TLS requirement, no SSE reconnect/heartbeat for the client (only listed as a future seam at `07-mcp.md:236`), and the server-side SSE transport (`07-mcp.md:182`) has no auth at all. DEFER to Phase 12, with the auth-header convention pinned now (one line).

- **MCP error propagation** — covered: `"ERROR: MCP call failed: …"` table (`07-mcp.md:152-157`) is consistent with the kernel's error-as-string contract (`01-kernel.md:42-47`). No action.
- **MCP server-start failure / crash recovery** — covered: warn-and-skip + `/mcp reconnect` (`07-mcp.md:142-157`). Adequate for Phase 12.
- **Bearer auth + CORS basics** — covered as config (`06-app.md:264-267`). Sufficient as a *table*; only the multi-session binding (above) is missing.
- **Bash timeout / exit-code mapping** — covered (`03-feed.md:74`). No action.
- **OS keychain for keys; keys never in JS** — covered (`08-frontend.md:26-28`, `secrets_*` IPC `08-frontend.md:43-46`). The gap is server-side logging (§2), not the keychain design.

- **aisdk OTel spans** — correctly a seam (`08-frontend.md:362`, BACKLOG). DEFER.

## 4. New gaps (not on the focus list)

- **No error taxonomy crosses the boundaries coherently.** The kernel returns `Result<String, KernelError>` (`01-kernel.md:79`); `Session::send` returns `Result<(String, VerificationReport)>` (`06-app.md:45`). What does a provider 500, an auth failure, or a timeout look like as (a) a CLI message, (b) an HTTP status + body on `/chat`, (c) a Tauri `invoke` rejection? `08-frontend.md` shows no error event and no `invoke` error handling. Without a shared error→surface mapping, each adapter will invent its own. PIN NOW (a small enum + per-surface mapping table).
- **`rk://` event contract is duplicated, not shared.** 8 events in `06-app.md:274` vs 8 in `08-frontend.md:62`, plus `rk://turn_start` used in `08-frontend.md:241` and `rk://consolidation`/`rk://plan_exit` that appear in one table but not consistently the other. `rk://turn_start` is not in either event table. These must be one canonical list. PIN NOW (cheap: dedupe into one table the gateway and frontend both cite).
- **Token-stream backpressure / cancellation undefined.** `rk://token` fires per token (`06-app.md:276`) and over an `mpsc::channel(1)` to the Session task (`06-app.md:139`). There is no statement of what happens if the SSE client or Tauri webview is slow (drop? buffer? block the model?) and no user-cancel path (stop a running turn) on any surface. DEFER detail to Phase 5/14/15, but flag the cancel-token requirement now (the bash tool already has `CancellationToken` at `03-feed.md:160` — turn-level cancel should mirror it).
- **`config_set` / `secrets_set` can mutate a running Session with no scope statement.** `/config set` is "for this session" (`06-app.md:203`) but the IPC `config_set` returns `AppConfig` (`08-frontend.md:42`) with no statement of whether model/workspace changes mid-session are allowed or require a restart. Changing `RUSTYKEYS_WORKSPACE` mid-session would void the canonicalized `WorkspacePolicy` boundary (`02-constrain.md:48`) — a security-relevant ambiguity. PIN NOW (one line: which keys are hot-reloadable vs restart-only).
- **No cross-boundary integration-test strategy anywhere in the corpus.** The focus list asks for it and nothing in BACKLOG Phases 12/14/15 mentions a fake MCP server, gateway contract tests, or IPC smoke tests. The kernel/aisdk boundary also needs a mock-provider fixture for deterministic CI (aisdk calls are the one non-deterministic dependency). PIN NOW as a documented test seam per boundary; build per phase.
- **`/health` cannot express degraded states.** `06-app.md:246` returns `{ status: "ok", … }` — no representation of "provider unreachable," "MCP server down," or "over budget." A gateway behind a load balancer needs liveness vs readiness. DEFER to Phase 14.

## 6. Cross-persona dependencies

- **Security reviewer** — overlaps on three items I marked P0: secret redaction in evidence/IPC, web-tool SSRF/egress, and `config_set` mutating the workspace boundary mid-session. These are integration *and* security findings; we should converge on one redaction rule and one egress rule rather than two. The `Bypass` mode (`02-constrain.md:93`) and gateway auth model also want a joint look.
- **Kernel/architecture reviewer** — owns whether the aisdk retry/timeout/version policy lives in the kernel crate or a shared `aisdk-client` wrapper (every layer calls aisdk: kernel, consolidation, judge, embed, summarisation). The error-taxonomy enum is shared surface area with their `KernelError` design.
- **Verification/observability reviewer** — the redaction rule changes what `evidence.jsonl` and the episode package contain; they should confirm redaction does not break attribution or the `/evidence` schema they rely on.
- **Product/PRD-consistency reviewer** — owns deduping the `rk://` event table and the `RUSTYKEYS_*` env-var additions I propose (`_WEB_ALLOWLIST`, MCP/gateway SSE auth, session TTL) into the canonical config table in `06-app.md`.
