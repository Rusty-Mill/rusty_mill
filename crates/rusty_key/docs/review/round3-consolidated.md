# Round 3 — consolidated faithfulness audit

## 1. Executive verdict

Rusty Keys is **architecturally faithful and now near-complete** against the clean paper. The four-verb decomposition realises the paper's "harness mediates how an agent observes, acts, receives feedback, and establishes completion" (p.4–5); all eleven responsibilities (Table 1, p.6) have a clear home; all five principles and the eight-trace / five-label / eight-Ftype taxonomies are present and — where checked verbatim — exact. The clean text **vindicates** the three faithfulness divergences that were only *guessed* in Rounds 1–2: entropy = 7 categories × 0–3 severity (p.10), M-HIR = missing-harness / total episodes (p.4), intervention log = assistance + avoidability + burden + harness-gap (p.10) are all confirmed, so the single biggest blocker to "freezing" the faithfulness ADRs is gone and the §12 PDF caveat is obsolete. What remains is **not vocabulary drift but plumbing-and-method depth**: (a) the H0–H3 ladder is built as *additive capability* rather than the paper's *controlled-visibility ablation* (R1 hiding + R5 all-levels adjudication unbuilt — the one finding that, left alone, weakens the paper's central separability claim); (b) several declared episode-package traces (`action_trace`, `context_trace`, parts of `tool_trace`/`verification_trace`) have a schema but **no named producer**; (c) two implicit divergences (memory as a generative superset; context-selection mechanism vs the paper's named protocol artifact) and one internal contradiction (the M-HIR numerator counts `unavoidable`) are real but contained. None is a misreading; all are honestly flagged in RK's own docs.

### 2.1 Evidence walk for the contested / High-severity findings

So the synthesis stands on its own, the load-bearing items are grounded in the quoted text (all verified firsthand against the extraction, not relayed from the audits):

- **F1 entropy (p.10, verbatim):** *"the entropy audit records categories of agent-introduced maintenance burden—code, documentation, dependency, test, file residue, architecture, workflow—together with a 0–3 severity."* Seven category tokens + 0–3. RK's 6→7 map predicted this exactly: merge *code* + *file residue* → `Residue`, rename *workflow* → `TaskContradiction`, and four 1:1 (*test*→`TestWeakening`, *documentation*→`StaleDocs`, *dependency*→`DependencyChurn`, *architecture*→`BoundaryViolation`). The merge loses *labeling* granularity, not *data* — entropy-delta is `−Σ severity`, category-agnostic — so it is lossless for cross-paper comparison.
- **F2 M-HIR (p.4, verbatim):** *"M-HIR = missing-harness interventions / total episodes."* Unambiguously "total episodes," not turns/responses/tasks — which *confirms* RK diverges (RK uses turns) rather than misread. The numerator gloss — *"A harness that lowers M-HIR is one that supplies runtime support the human would otherwise have to provide"* (p.4) — is what grounds F23 below.
- **F8 R1 / F9 R5 (p.7, verbatim):** R1 = *"each level exposes only the artifacts assigned to that level; lower levels do not see higher-level artifacts"*; R5 = *"every level is adjudicated under the same final outcome taxonomy."* Table 5 (p.11) makes R5 concrete: **H0 is labelled `autonomous_verified_success`** via *"evaluator-side deterministic checks pass; full regression succeeds"* with no agent report at all. RK enforces neither the subtractive half of R1 (it gates capability additively but leaves H2 artifacts readable in the shared tree) nor R5 (it classifies "every H3 turn" only). This is why both audits that touch the ladder rate it the top fidelity item.
- **F10 dual-role checks (p.10, verbatim):** *"Deterministic checks serve two roles: at H3 they are agent-visible harness artifacts that support the agent's own verification; at all levels they are evaluator-side adjudication checks that classify the final outcome. The distinction preserves the ladder while permitting consistent adjudication."* The paper's *own* resolution is that the evaluator runs the checks at every level — so making `CheckRegistry::run_all()` an all-levels evaluator pass is *faithful restoration*, not a new feature.
- **F11 action≠tool (p.9, verbatim):** the action trace *"records externally meaningful operations such as read_file, edit_file, run_tool, write_report, update_task_state, inspect_diff, and declare_complete"* — Table 4 ties it to *"all (sequence of agent operations) / overall episode coherence"*, while the tool trace is a *separate* row tied to Ftool. They are distinct classes; collapsing `action_trace` into a copy of `tool_trace` would silently destroy the episode-coherence diagnostic.
- **F23 numerator contradiction (firsthand, PRD 04 L169–173):** RK says a `tool_block` is `unavoidable` and *"the policy working as intended is not a missing-harness signal"* (L170) — then *"Both `avoidable` and `unavoidable` count toward M-HIR; only `benign` is excluded"* (L172). A correct permission block is the harness *working*; the paper's Table 1 lists the permission boundary's failure mode as "Unsafe invalid episodes," not "intervention." So counting it over-states M-HIR against p.4's intent. This is the **only substantive logic correction** in the round.

## 5. Resolving the persona disagreements

The five audits are largely complementary (each owns a different slice), but three points need an explicit ruling:

- **Is RK faithful on adjudication? (F5 vs F9/F10.)** SW and HARN call the 5-label taxonomy and the autonomy-vs-success gating **confirmed-faithful**; SYS calls adjudication a **real drift**. *Resolution: both are right at different scopes.* The label *set* and the per-turn *gating logic* are faithful (F5 stands) — RK never lets a correct-but-unverified patch silently pass. What SYS correctly identifies is a *protocol-level* gap (F9/F10): the paper's claim is that the **same evaluator-side checks run under every level** and the *delta* between "behaviour passes" and "agent proved it" is what the ladder measures. RK only adjudicates H3 and only from agent self-report, so the paper's headline Table 5 contrast is unreproducible. Verdict: keep F5 as faithful **and** record F9/F10 as drift — they are not in tension. SYS's own caveat is adopted: the all-levels fix lands most cleanly in the **eval-plan golden-episode replay** (a task-grained context where `checks.toml` is meaningful), not necessarily the live per-turn hot path.
- **Severity of the ladder gaps (F8/F9/F10).** SW frames R1 hiding as "sound to defer"; SYS calls it "the single most important fidelity item." *Resolution: side with SYS on severity (High).* It is the gap that most directly weakens the paper's *central* methodological claim (separability, p.2), and it must be sequenced **before** any Hn-vs-Hm lift is reported as evidence. It remains *acknowledged* drift (ADR-0028, ARCH §3, eval-plan §4 all flag it), so it is honest-divergence-in-progress, not a hidden bug — but it is not "minor."
- **One workstream or three?** SYS argues F8 (visibility hiding) + F10 (evaluator-side checks) + F26 (workspace isolation) are **the same eval-substrate concern** and should land as one workstream, sequenced isolation→visibility→adjudication. INT independently argues F11/F13/F14/F16/F18 are **the same missing component** (the `compose` package-assembly projector). *Resolution: these are two distinct workstreams* — SYS's is the *eval ladder* (how levels are run and scored), INT's is the *episode-package builder* (how raw evidence becomes typed traces). They intersect only at F12 (`context_trace` producer), which both need. Recommend two ADRs, not one (Decision D3 + D5).
